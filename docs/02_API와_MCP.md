# API와 MCP, 그리고 API 키 — 초심자를 위한 쉬운 설명

> 결론부터: **여러분은 대부분 API 키가 필요 없습니다.** Claude나 ChatGPT는 그냥 **월 구독(정액제)** 앱으로 쓰세요.
> API 키는 "개발자가 직접 프로그램을 만들 때" 쓰는 **선택 사항/고급 기능**입니다.

---

## 1. API란? — "식당 주문창구"

API(Application Programming Interface)는 어렵게 들리지만, 비유하면 아주 단순합니다.

> **API = 식당의 주문창구(주방과 손님을 연결하는 창구)**

- 여러분(프로그램)은 주방(AI 회사의 서버)에 직접 들어갈 수 없습니다.
- 대신 **주문창구**에 "이거 주세요"라고 요청하면, 주방에서 만들어서 창구로 내어줍니다.
- 이 "주문 양식과 절차"가 바로 API입니다. 즉, **프로그램끼리 대화하는 정해진 규칙(창구 매뉴얼)**입니다.

예를 들어 "Claude API"는 —

> 내 프로그램이 "이 질문에 답해줘"라는 주문서를 Anthropic의 주문창구로 보내면,
> Anthropic 서버(주방)가 답변을 만들어서 돌려주는 것

입니다. 이건 사람이 채팅창에 타이핑하는 게 아니라, **코드가 자동으로 주문하고 받는 방식**입니다.

### 그래서 API는 누가 쓰나요?

- 개발자가 "내 앱/스크립트 안에 AI 기능을 자동으로 넣고 싶을 때"
- 예: 매일 새벽에 자동으로 논문 100편을 요약하는 스크립트를 돌리고 싶다 → API 사용
- 반대로, "그냥 내가 채팅창에서 대화하며 쓰고 싶다" → API 필요 없음, **구독 앱**이면 충분

---

## 2. MCP란? — "표준 플러그 규격"

MCP(Model Context Protocol)는 API보다 한 단계 더 나아간 개념입니다.

> **MCP = 전 세계 어디서나 통하는 표준 플러그(콘센트) 규격**

전자제품을 생각해보세요. 만약 냉장고, 청소기, TV마다 플러그 모양이 다 다르다면, 집집마다 어댑터를 따로 만들어야 합니다. 그런데 "표준 플러그 규격"이 있으면, 어떤 제품이든 그 규격에 맞춰 만들기만 하면 **어느 콘센트에나 바로 꽂아 쓸 수** 있습니다.

- **MCP 이전**: AI가 Google Drive를 쓰려면 Google Drive 전용 연결 코드를, Notion을 쓰려면 Notion 전용 연결 코드를, 이런 식으로 **서비스마다 매번 새로 개발**해야 했습니다.
- **MCP 이후**: "이 규격대로만 만들면 어떤 AI든 바로 연결된다"는 **공통 플러그 규격**이 생겼습니다. Notion, GitHub, 구글 캘린더 등이 이 규격에 맞춰 "플러그"를 만들어두면, Claude 같은 AI가 그 플러그에 바로 꽂아서 쓸 수 있습니다.

즉, MCP는 **"AI와 외부 서비스(도구)를 연결하는 표준 규격"**입니다. API가 "주문창구 하나하나"라면, MCP는 "그 창구들을 규격화해서 어떤 AI 앱에도 똑같이 꽂아 쓸 수 있게 만든 것"이라고 보면 됩니다.

### 초심자가 알아야 할 것

- 일반 사용자는 MCP를 직접 만들 일이 거의 없습니다.
- Claude Desktop 앱이나 Claude Code 같은 도구에서 "이 서비스 연결하기" 버튼을 누르면, 이미 MCP 규격으로 만들어진 연결을 그냥 **가져다 쓰는 것**뿐입니다.
- MCP 연결은 **계정 전체에 항상 켜져 있는 통로**입니다. 한 번 연결해두면 AI가 그 서비스에
  언제든 접근할 수 있고, 이번 작업에 정확히 어떤 범위까지 열려 있는지 눈으로 확인하거나
  작업 단위로 껐다 켰다 하기가 어렵습니다.
- 그래서 이 툴킷은 **MCP 연결을 지양합니다.** 메일·GitHub·Asana·Notion처럼 이미
  REST 커넥터(`scripts/connectors/`)가 있는 서비스는 MCP로 연결하지 말고 그 커넥터를
  쓰세요 — 자세한 이유는 아래 5장, 실제 사용법은
  [`docs/05_외부서비스_연동.md`](05_외부서비스_연동.md)를 참고하세요.
  MCP는 **정말로 REST 커넥터를 만들 수 없는 서비스**이거나 **웹페이지를 직접 봐야 하는
  브라우저 탐색**처럼 대체 수단이 없을 때만, 최후의 수단으로만 씁니다.

## 3. API 키란? — "출입증"

API를 쓰려면(즉, 주문창구를 이용하려면) 신원 확인이 필요합니다. 이게 **API 키**입니다.

> **API 키 = 건물 출입증(사원증)**

- 출입증이 있어야 건물(서버)에 들어가서 서비스를 받을 수 있습니다.
- 출입증에는 "누가 얼마나 썼는지" 기록이 남고, **쓴 만큼 요금이 청구**됩니다.
- 출입증을 잃어버리면(유출되면) 다른 사람이 내 이름으로 건물을 드나들며 비용을 쓸 수 있으므로, **절대 남에게 보여주거나 공개 저장소에 올리면 안 됩니다.**

### API 키가 필요한 경우 (선택/고급)

- 나만의 프로그램/스크립트를 만들어서 AI 기능을 자동화하고 싶을 때
- 예: "매주 논문 100편을 자동 요약하는 봇", "회사 내부 시스템에 AI 기능 연동"

### API 키가 필요 없는 경우 (대부분의 초심자)

- Claude.ai, ChatGPT 웹/앱에서 그냥 채팅하며 쓰는 것
- 이때는 **월 구독료(정액제)**만 내면 됩니다.

## 4. 왜 "구독(정액제)"을 먼저 권장하는가

| 구분 | 월 구독(정액제) | API 키(종량과금) |
|---|---|---|
| 요금 방식 | 매달 정해진 금액 고정 (예: Claude Pro/Max, ChatGPT Plus) | **쓴 만큼** 과금 (토큰 단위로 계산) |
| 요금 예측 | 쉬움 — 매달 똑같은 금액 | **어려움** — 사용량 따라 널뛰기 |
| 초심자 적합성 | 매우 적합 | 프로그래밍 지식 필요, 관리 부담 있음 |
| 실수 시 위험 | 거의 없음 | **키 유출·무한루프 스크립트 등으로 예상 밖의 큰 비용** 발생 가능 |
| 추천 대상 | **일반 사용자, 채팅으로 쓰는 모든 사람** | 개발자, 자동화 프로그램을 직접 만드는 사람 |

> ⚠️ **종량과금 주의**: API 키를 발급받아 쓰면 "쓴 만큼" 요금이 청구됩니다. 코드에 버그가 있어서 같은 요청이 수천 번 반복되거나, 키가 유출되어 다른 사람이 무단으로 쓰면 **하루 만에 예상치 못한 고액 청구**가 나올 수 있습니다. 실제로 "API 키가 깃허브에 실수로 공개되어 큰 비용이 청구된" 사례가 흔합니다.
>
> 그래서 결론은 이렇습니다.
> - **일반적인 사용 = 무조건 월 구독(정액제)**. 예산이 명확하고, 실수해도 추가 비용이 없습니다.
> - **API 키 = 정말 필요할 때만(자동화 스크립트 등), "선택/고급 기능"으로 접근**. 쓸 때도 사용량 한도(spending limit)를 반드시 설정하세요.

## 5. 이 툴킷이 REST 커넥터를 기본값으로 쓰는 이유

앞서 "MCP는 편하다"고 설명했는데, 왜 굳이 REST 커넥터 스크립트를 우선하라는 걸까요?
편함과 안전함이 이 지점에서만큼은 반대 방향이기 때문입니다.

| 구분 | MCP 연결(버튼) | REST 커넥터(`scripts/connectors/`) |
|---|---|---|
| 접근 범위 | 계정 전체에 상시 연결 — 이번 작업과 무관해도 항상 열려 있음 | 스크립트 실행 그 순간, 그 명령이 요청한 만큼만 |
| 토큰 위치 | 앱 내부(직접 보이지 않음) | `config/credentials.json`(gitignore) 또는 환경변수 — 내가 위치를 알고 회수 가능 |
| 쓰기(발송/삭제) 제어 | 서비스마다 다름, 눈으로 확인하기 어려움 | 커넥터마다 `--write`/`--send` 게이트 + 기본은 읽기·초안까지만 (`AGENTS.md` §9) |
| 필요 없어지면 | "연결 해제" 버튼을 눌러야 함(잊기 쉬움) | 토큰을 그냥 폐기(rotate/revoke)하면 끝 |

**토큰 발급이 어렵다는 선입견은 접어두어도 됩니다.** 대부분 브라우저로 로그인 →
계정 설정 → "개인 액세스 토큰 만들기" 몇 번 클릭이면 끝나고, `scripts/connectors/README.md`에
서비스별 발급 위치가 정리돼 있습니다.

**실전 원칙 — MCP는 지양, REST 커넥터가 기본**:
- 메일·GitHub·Asana·Notion처럼 이미 커넥터가 있는 서비스 → **MCP로 연결하지 말고 그
  커넥터를 쓴다.** 해당 서비스의 MCP 연결이 이미 켜져 있다면 커넥터로 전환한 뒤 **바로
  해제**하세요 (앱의 "연결 해제" 버튼 — 본인이 직접 눌러야 하는 계정 설정 동작입니다).
- 아직 커넥터가 없는 서비스(예: 캘린더, 공유 시트) → 지금 당장은 MCP로 버티되, 이것도
  "괜찮은 기본값"이 아니라 **커넥터가 생기기 전까지의 임시 방편**입니다. 필요해지면
  `scripts/connectors/README.md`의 안내를 따라 커넥터를 만들어 바로 넘어가고, 넘어간
  뒤에는 그 서비스의 MCP도 해제하세요.
- 웹페이지를 눈으로 보고 클릭해야 하는 탐색성 작업(브라우저 자동화)만 예외입니다 — REST로
  대체할 수 있는 성격의 일이 아니므로, 이 경우에 한해서만 MCP(Chrome 연결)를 최후의 수단으로
  씁니다.

## 6. Codex에 대한 짧은 메모

- **Codex**는 OpenAI가 만든, 코드 작성을 돕는 AI 도구(에이전트)입니다. ChatGPT 구독(Plus 이상)에 포함되어 있거나, 별도로 API를 통해 쓸 수도 있습니다.
- 이 문서의 원칙은 Codex에도 동일하게 적용됩니다: **일반적으로 코드를 짜거나 질문하는 용도라면 ChatGPT 구독 안에서 쓰는 것으로 충분**하며, API 키를 따로 발급받아 쓰는 것은 "내 프로그램/파이프라인에 자동으로 연동하고 싶을 때"만 고려하는 **고급 옵션**입니다.
- Claude Code와 Codex를 함께 쓰는 경우에도, 각자 "구독 기반 사용"이 기본이고 API 연동은 필요할 때만 추가하면 됩니다.

## 7. 한 줄 요약

- **API** = 프로그램끼리 주문을 주고받는 **주문창구**
- **MCP** = 어떤 서비스든 AI에 똑같이 연결되는 **표준 플러그 규격**이지만, **계정 전체에
  상시로 열리는 통로**라서 이 툴킷의 기본값은 아님
- **API 키** = 그 창구를 이용하기 위한 **출입증**(유출 주의, 종량과금) — 발급은 브라우저
  로그인 몇 번 클릭이면 끝나는 정도로 어렵지 않음
- **채팅으로 Claude/ChatGPT를 쓰는 것** = API 키 없이 **월 구독(정액제)**으로 충분
- **외부 서비스 연동(메일·GitHub·Asana·Notion 등)** = 커넥터가 있으면 **REST 커넥터 우선**,
  없으면 MCP를 임시로 쓰고 나중에 커넥터로 넘어가기 — 자세히는 5장과
  [`docs/05_외부서비스_연동.md`](05_외부서비스_연동.md)
