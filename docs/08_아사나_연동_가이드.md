# 08. 아사나(Asana) 연동 가이드 — 내 작업 목록을 AI에게 읽히고, 새 작업/댓글을 만들게 하기

> 한 줄 요약: **읽기(me/tasks)는 자유롭게, 작업/댓글/하위작업 생성은 --write 를 붙였을 때만, 완료 처리·삭제 기능은 아예 없습니다.**

이 문서는 `scripts/connectors/asana_connector.py` 를 이용해 아사나(Asana)의 **내 작업(Task) 목록**을
AI에게 읽히고, 새 작업·댓글·하위작업을 만드는 방법을 초심자 눈높이에서 설명합니다.
연결·보안의 큰 원칙은 [05_외부서비스_연동](05_외부서비스_연동.md)에서 이미 다뤘으니, 이 문서는
"아사나" 케이스, 특히 **서식(형식)이 깨지는 문제**에 집중합니다.

---

## 1. 아사나 연동이 뭘 해주나요?

아사나에서 작업(Task)을 관리하고 있다면, 이 연동으로 AI가 할 수 있는 일은 이렇습니다.

1. **읽기**: "내 작업이 뭐가 있지?" 를 AI가 아사나에서 직접 조회해서 알려줍니다.
2. **작업 생성**: "이 작업 하나 만들어줘" 하면 새 작업을 만들어줍니다.
3. **댓글 달기**: 기존 작업에 진행 상황이나 메모를 댓글로 남겨줍니다.
4. **하위작업 생성**: 큰 작업 아래에 세부 단계를 하위작업으로 쪼개줍니다.

읽기(2, 3, 4의 쓰기 동작과 달리)는 언제나 즉시 실행되지만, **쓰기 동작(작업/댓글/하위작업 생성)은
기본적으로 미리보기(dry-run)만 하고, 실제로 실행하려면 `--write` 라는 플래그를 명시적으로
붙여야 합니다.** (05번 문서의 "나가는 건 초안까지만" 원칙과 같은 결입니다.)

> **왜 MCP 대신 이 커넥터를 쓰는 게 나은지 — 실제 있었던 사례**: 아사나의 MCP 쪽 작업 생성
> 도구는 "미리보기 카드"만 만들고, 화면에서 확정 버튼을 한 번 더 눌러야 실제로 생성됩니다.
> 이 확정 클릭이 세션 종류에 따라 빠질 수 있는데, 이 경우 AI는 "만들었다"고 응답하지만 실제
> 아사나에는 아무 작업도 생기지 않습니다 — 겉보기엔 성공했는데 실제로는 아무 일도 없었던
> 조용한 실패였습니다. 이 커넥터의 `--write` 방식은 그런 애매한 중간 상태가 없습니다:
> 안 붙이면 확실히 미리보기만, 붙이면 확실히 생성입니다. MCP를 썼다면 생성 직후 `tasks`로
> 다시 조회해서 실제로 반영됐는지 항상 확인하세요.

그리고 한 가지 더 — **작업을 나 아닌 다른 사람에게 배정하거나(`--assignee`), 댓글을 다는 것은
남에게 보이는 "외부 동작(outward action)"** 입니다. 이 경우 커넥터가 알림을 한 번 더 보여줍니다.

이 스크립트에는 **작업 완료 처리나 삭제 기능이 아예 없습니다.** 실수로 남의 작업을 지우거나
완료 처리할 걱정 없이 읽기/생성만 시켜볼 수 있습니다.

## 2. 준비 — Asana Personal Access Token(PAT) 발급받기

아사나 API를 쓰려면 "Personal Access Token"(개인 접근 토큰)을 하나 발급받아야 합니다.
`docs/02_API와_MCP.md`의 비유를 그대로 쓰면, **토큰 = 출입증**입니다.

1. 브라우저에서 `app.asana.com` 에 로그인한 뒤, 우측 상단 프로필 아이콘 → **"내 설정(My Settings)"**
   으로 들어갑니다.
2. **"앱(Apps)"** 탭 → 하단의 **"개발자 앱 관리(Manage Developer Apps)"** 를 클릭합니다.
3. **"새 개인 액세스 토큰 만들기(Create New Personal Access Token)"** 를 누르고 이름을 하나
   붙입니다 (예: "sci-toolkit-connector" 등 알아보기 쉬운 이름).
4. 생성하면 토큰 문자열이 한 번만 보여집니다. 이게 **출입증**입니다 — 그 자리에서 복사해두세요.
5. 이 토큰을 아래 둘 중 하나로 등록합니다.
   - `config/credentials.json` 의 `asana.token` 자리에 붙여넣기 (이 파일은 배포·커밋에서 제외됩니다), 또는
   - 환경변수 `SCITK_ASANA_TOKEN` 을 설정하고, `credentials.json` 에는 `"token": "ENV:SCITK_ASANA_TOKEN"` 처럼
     적어두기 (토큰 값 자체가 파일에 안 남아 더 안전 — `docs/05_외부서비스_연동.md` 참조).

> 토큰을 채팅창에 그대로 붙여넣지 마세요. 05번 문서의 "토큰 = 출입증" 원칙 그대로입니다.

### workspace gid 확인하기

아사나에서 대부분의 명령은 **workspace gid**(내가 속한 작업공간의 고유번호)가 필요합니다.
직접 알아낼 필요 없이, `me` 명령을 실행하면 커넥터가 내가 속한 workspace 목록을 이름과 gid로
바로 보여줍니다.

```bash
python scripts/connectors/asana_connector.py me
```

출력 예시(형태만 참고, 실제 값은 각자 다릅니다):

```
이름: ...
gid: ...
email: ...
workspaces:
  - <워크스페이스 이름> (gid=<WORKSPACE_GID>)
```

이 `<WORKSPACE_GID>` 를 이후 명령의 `--workspace` 인자에 씁니다.

## 3. 기본 사용법

모든 명령은 toolkit 루트에서 실행합니다.

```bash
# 1) 내 프로필 + workspace 목록 확인 [READ]
python scripts/connectors/asana_connector.py me

# 2) 내 작업 목록 조회 [READ]
python scripts/connectors/asana_connector.py tasks --workspace <WORKSPACE_GID>

# 3) 새 작업 생성 — 먼저 --write 없이 미리보기(dry-run)
python scripts/connectors/asana_connector.py add-task --workspace <WORKSPACE_GID> --name "예시 작업"

# 3-1) 실제로 생성하려면 --write 를 붙인다
python scripts/connectors/asana_connector.py add-task --workspace <WORKSPACE_GID> --name "예시 작업" --write

# 4) 기존 작업에 댓글 달기 (일반 텍스트)
python scripts/connectors/asana_connector.py add-comment --task <TASK_GID> --text "진행 상황 메모" --write

# 5) 하위작업 만들기
python scripts/connectors/asana_connector.py add-subtask --parent <TASK_GID> --name "1단계: 데이터 정리" --write
```

`tasks` 명령에서 `--workspace` 를 빼고 실행하면, 오류 대신 사용 가능한 workspace 목록을
안내해줍니다 — gid를 몰라도 시작할 수 있습니다.

`add-task` 는 `--notes`(설명)와 `--assignee`(담당자, `me` 또는 다른 사람의 gid/email)도 받습니다.
`--assignee` 에 `me` 가 아닌 값을 넣으면 "남에게 배정되는 작업입니다 — 외부로 나가는(outward)
동작입니다" 라는 알림이 먼저 뜹니다.

## 4. ⭐⭐ 가장 중요한 섹션 — 댓글·하위작업 형식이 깨지는 이유와 해결

사용자가 실제로 자주 겪었던 문제가 바로 이겁니다: 서식 있는 댓글을 아사나 API로 직접 보내면
"형식이 이상해지거나" 아예 오류가 나는 경우가 많았습니다. 이 커넥터는 그 함정들을 자동으로
막아주도록 만들어져 있습니다.

### 짧은 일반 댓글 → 그냥 `--text` 만 쓰면 됩니다

```bash
python scripts/connectors/asana_connector.py add-comment --task <TASK_GID> --text "완료했습니다" --write
```

이건 plain text(일반 텍스트)로 그대로 전송되고, 아사나가 알아서 표시해줍니다. 별도 신경 쓸 게
없습니다.

### 서식(굵게, 목록 등)이 필요하면 `--html`

```bash
python scripts/connectors/asana_connector.py add-comment --task <TASK_GID> \
  --text "<strong>결과 요약</strong>: 진행률 80%, 다음 단계는 분석입니다." \
  --html --write
```

`--html` 을 붙이면 커넥터가 내부적으로 아사나의 `html_text` 서식 규칙을 **자동으로 검증하고
보정**합니다. 아사나의 서식 규칙에는 초심자가 모르고 걸리기 쉬운 함정이 4가지 있습니다.

| # | 함정 | 무슨 일이 생기나 | 커넥터가 해주는 것 |
|---|---|---|---|
| (a) | 전체를 `<body>...</body>` 로 감싸야 함 | 안 감싸면 형식 오류 | `--html` 사용 시 `<body>` 가 없으면 **자동으로 감싸줍니다** |
| (b) | `<p>` 태그(문단 태그) 절대 금지 | `<p>` 를 넣으면 `xml_parsing_error` 로 요청 자체가 실패 | 커넥터가 `<p>` 발견 시 **실행 전에 딱 막고** "줄바꿈은 &#10; 를 쓰세요" 라고 알려줍니다 |
| (c) | 줄바꿈은 일반 줄바꿈(엔터)이 아니라 특수 코드 `&#10;` 사용 | 그냥 엔터를 넣으면 형식이 깨짐 | 커넥터가 입력한 줄바꿈(엔터)을 **자동으로 `&#10;` 로 변환**해줍니다 |
| (d) | `'→'`(화살표 기호) 문자 절대 금지 | 넣으면 XML 파싱 에러로 요청 실패 | 커넥터가 `→` 를 발견하면 **실행 전에 딱 막고** "`->` 나 단어로 바꾸세요" 라고 알려줍니다 |

그리고 허용되는 태그는 `<strong>`(굵게), `<em>`(기울임), `<u>`(밑줄), `<code>`, `<a>`(링크),
`<ul>`/`<ol>`/`<li>`(목록), `<h1>`/`<h2>`(제목), `<table>`/`<tr>`/`<td>` 정도로 **일부만
허용**됩니다. 이 밖의 태그를 쓰면 아사나 쪽에서 거부될 수 있으니, 서식은 이 목록 안에서만
쓰는 걸 권장합니다.

하위작업의 설명도 마찬가지로 `--html-notes` 플래그를 붙이면 같은 규칙이 적용됩니다.

```bash
python scripts/connectors/asana_connector.py add-subtask --parent <TASK_GID> \
  --name "2단계: 분석" --notes "<strong>목표</strong>: 결과 검증" --html-notes --write
```

### 한글이 깨지던 문제

예전에 `curl` 같은 도구로 아사나 API를 직접 호출하면, 윈도우 환경에서 한글이 `\uXXXX` 같은
이스케이프 코드로 깨져서 전송되거나 인코딩이 어긋나는 경우가 있었습니다. 이 커넥터는
`ensure_ascii=False` + `charset=utf-8` 을 요청에 항상 명시하도록 만들어져 있어서, **한글 작업
이름·댓글·설명이 깨지지 않고 그대로 전송됩니다.** 이 부분은 자동으로 처리되므로 따로 신경 쓸
필요가 없습니다.

### 결론

- 짧고 서식 없는 댓글/메모 → 그냥 `--text` (또는 `--notes`) 만 쓰세요.
- 굵게/목록 같은 서식이 필요하면 `--html`(또는 `--html-notes`) 을 붙이세요. 위 (a)~(d) 규칙은
  커넥터가 자동으로 지켜주거나, 위반 시 실행 전에 바로 알려줍니다.

## 5. ⭐ 안전 원칙

- **읽기(`me`/`tasks`)는 언제든 자유롭게 실행해도 됩니다.** 아무것도 바꾸지 않습니다.
- **쓰기(`add-task`/`add-comment`/`add-subtask`)는 `--write` 를 붙이지 않으면** 무엇이
  생성될지 미리보기(JSON)만 출력하고 실제로는 아무 일도 일어나지 않습니다.
- **다른 사람에게 배정하거나(`--assignee`), 댓글을 다는 것은 "외부 동작"** 입니다 — 팀원이
  실제로 보게 되는 동작이므로, `--write` 를 붙이기 전에 미리보기 내용을 한 번 더 확인하는 걸
  권장합니다.
- **작업 완료 처리(complete)나 삭제(delete) 기능은 이 스크립트에 의도적으로 없습니다.** 그런
  작업이 필요하면 아사나에서 직접 수행하세요.

## 6. 안전 요약 표

| 동작 | 기본 동작 | 실행 조건 |
|---|---|---|
| `me` (내 프로필/workspace 조회) | 바로 실행 (읽기 전용) | 항상 자유 |
| `tasks` (내 작업 목록 조회) | 바로 실행 (읽기 전용) | 항상 자유 |
| `add-task` (`--write` 없이) | 미리보기만 출력, 실제로 생성 안 됨 | — |
| `add-task --write` | 실제로 작업 생성. `--assignee` 가 나 아니면 외부동작 알림 | 명시적 `--write` 필요 |
| `add-comment` (`--write` 없이) | 미리보기만 출력 | — |
| `add-comment --write` | 실제로 댓글 등록 (항상 외부동작 알림 — 남이 볼 수 있음) | 명시적 `--write` 필요 |
| `add-subtask` (`--write` 없이) | 미리보기만 출력 | — |
| `add-subtask --write` | 실제로 하위작업 생성. `--assignee` 가 나 아니면 외부동작 알림 | 명시적 `--write` 필요 |
| (작업 완료 처리) | **이 스크립트엔 아예 없음** | — |
| (삭제) | **이 스크립트엔 아예 없음** | — |

## 7. 한 줄 요약

- 아사나 연동 = **읽기(me/tasks)는 자유, 작업/댓글/하위작업 생성은 `--write` 필요, 완료·삭제는 아예 없음.**
- 서식 있는 댓글이 필요하면 `--html`(또는 `--html-notes`) 을 쓰되, `<p>` 금지·`&#10;` 줄바꿈·
  `→` 금지 같은 아사나의 까다로운 규칙은 커넥터가 자동으로 지켜주거나 실행 전에 막아줍니다.
- 짧은 일반 댓글은 그냥 `--text` 로 충분합니다 — 한글도 깨지지 않고 그대로 전송됩니다.
