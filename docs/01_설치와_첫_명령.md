# 01. 설치와 첫 명령 — 실제로 한 번 시켜보기

> 앞의 [00_시작하기](00_시작하기.md)에서 "AI 에이전트가 무엇인지" 감을 잡으셨다면,
> 이 문서에서는 **실제로 프로그램을 깔고, 이 툴킷을 얹고, 첫 명령을 내려보는** 것까지 해봅니다.
> 순서대로만 따라오시면 됩니다. 막히면 그냥 실험실 선배에게 물어보세요.

## 1. Claude Code 설치하기

[Claude Code](https://code.claude.com/docs/ko/overview)를 쓰는 길은 **세 가지**입니다. 셋 다 같은 Claude Code이고,
**같은 구독 계정으로 로그인**하며, **이 툴킷도 똑같이 얹힙니다.**
차이는 "어디서 대화하느냐"뿐입니다.

### 어느 걸 골라야 하나

| 이런 경우라면 | 이걸 쓰세요 |
|---|---|
| 터미널이 낯설다 / 일단 써보고 싶다 | **데스크톱 앱** |
| 이미 VS Code로 코드·데이터를 만진다 | **VS Code 익스텐션** |
| 터미널이 편하다 / 서버에서 쓴다 | **터미널(CLI)** |

> 고민되면 **데스크톱 앱**으로 시작하세요. 나중에 옮겨가도 설정을 다시 할 필요가 없습니다.
> 세 가지를 동시에 깔아도 서로 충돌하지 않습니다.

### 방법 A — 데스크톱 앱 (초심자 추천)

1. [claude.ai/download](https://claude.ai/download) 에 접속합니다.
2. 본인 컴퓨터에 맞는 버전(Windows / Mac)을 내려받아 설치합니다.
   (일반 프로그램처럼 다운로드 → 실행 → "다음" 클릭이면 끝납니다.)
3. 설치 후 앱을 열고, 본인 Claude 계정으로 로그인합니다. ([데스크톱 앱 시작하기](https://code.claude.com/docs/ko/desktop-quickstart))

> 이게 전부입니다. 아이콘 클릭 → 로그인 → 채팅창 등장. 여기까지 오면 절반은 끝났습니다.

### 방법 B — VS Code 익스텐션 (코드·데이터를 VS Code로 다루는 경우)

이미 [VS Code](https://code.visualstudio.com/)에서 파이썬 스크립트나 데이터를 만지고 있다면 이게 가장 편합니다.
편집 중인 파일을 AI가 바로 보고, 수정 결과도 에디터에서 바로 확인됩니다.

1. VS Code를 열고 왼쪽 **확장(Extensions)** 아이콘(네모 4개)을 클릭합니다.
2. 검색창에 **`Claude Code`** 를 입력하고, [Anthropic이 만든 것](https://marketplace.visualstudio.com/items?itemName=anthropic.claude-code)을 **설치(Install)** 합니다.
3. 설치되면 창을 다시 열고, 안내에 따라 Claude 계정으로 로그인합니다.
4. **작업 폴더로 `sci-toolkit` 을 엽니다** (파일 → 폴더 열기).

> [JetBrains](https://code.claude.com/docs/ko/jetbrains) 계열(PyCharm 등)을 쓰신다면 같은 이름의 플러그인이 있습니다.
> 플러그인 마켓플레이스에서 `Claude Code`를 검색하세요.

### 방법 C — 터미널(CLI)

터미널에 익숙하거나, 랩 공용 서버·HPC에서 쓸 거라면 이 방법입니다.

```
npm install -g @anthropic-ai/claude-code
```

설치 후 아무 폴더에서나 `claude` 라고 치면 실행됩니다. ([공식 설치 안내](https://code.claude.com/docs/ko/setup))
(`npm`이 없다면 [nodejs.org](https://nodejs.org) 에서 Node.js를 먼저 설치하세요.)

원격 서버에서 쓰는 방법은 [09_원격서버에서_쓰기](09_원격서버에서_쓰기.md) 를 보세요.

## 2. 이 툴킷을 "얹기"

Claude Code만 깔면, AI는 아직 "우리 실험실 방식"을 모르는 상태입니다.
이 툴킷 폴더를 얹어야 비로소 우리 규칙을 아는 상태가 됩니다.

> 비유: 신입 연구원(Claude Code)을 채용은 했는데,
> 아직 우리 실험실 매뉴얼(sci-toolkit)을 안 건네준 상태입니다. 이제 건네줄 차례입니다.

### 가장 간단한 방법 — 이 폴더를 열고 시작하기

1. Claude Code에서 **작업할 폴더를 `sci-toolkit` 폴더로 지정**합니다.
   설치 방식과 무관하게 하는 일은 같습니다.
   - **데스크톱 앱**: "폴더 열기" 또는 상단의 폴더 선택에서 `sci-toolkit`을 고릅니다.
   - **VS Code**: 파일 → 폴더 열기 → `sci-toolkit` 선택. 그 상태로 Claude Code 패널을 엽니다.
   - **터미널**: `sci-toolkit` 폴더 안으로 이동한 뒤 `claude` 실행.
2. 이 폴더 안의 `AGENTS.md`, `config/`, `skills/` 등을 AI가 자동으로 참고합니다.
   여러분이 따로 뭘 설정할 필요는 없습니다.

> ⚠️ 폴더를 통째로 옮기거나 이름을 바꾸면 참조가 깨질 수 있습니다.
> 처음엔 받은 그대로 두고 쓰세요.

### 다른 폴더에서도 쓰고 싶다면 (선택)

위 방법은 "`sci-toolkit` 폴더를 열었을 때만" 스킬이 붙습니다.
**어느 폴더에서 작업하든** 항상 쓰고 싶다면, 원하는 스킬만 골라 설치하세요.

```
python install/install.py --list                    # 뭐가 있는지 먼저 보기
python install/install.py --preset paper-writing    # 논문 작성 세트만
python install/install.py --skills docx,xlsx --apply
```

설치 위치는 `~/.claude/skills/` 이고, **세 가지 설치 방식(앱·VS Code·터미널)이
이 폴더를 공유**합니다. 한 번 설치하면 어디서 열든 적용됩니다.
(`--apply` 없이 실행하면 미리보기만 하고 실제로 복사하지 않습니다.)

### 잘 얹혔는지 확인 (선택)

`sci-toolkit` 폴더에서 아래를 실행하면 상태를 점검할 수 있습니다.

```
python doctor.py
```

`PASS`가 뜨면 정상입니다. (`FAIL`이 뜨면 그 줄을 캡처해서 선배에게 보여주세요.)
터미널을 안 쓰신다면 이 단계는 건너뛰어도 됩니다 —
Claude Code에게 "doctor.py 실행해서 결과 알려줘"라고 시켜도 됩니다.

### 파이썬 버전 — 오차·단위, 실험 설계 기능은 3.12 이상

`uncertainty-and-units`(오차 전파·단위 변환·± 표기)와 `doe-and-replication`(실험 설계·반복수·플레이트 배치)
두 기능은 [파이썬](https://www.python.org/downloads/) **3.12 이상**이 필요합니다. 쓰는 라이브러리(`pint`)가 3.12부터만 설치되기 때문입니다.
파이썬이 어떤 버전인지는 터미널에서 `python --version`으로 볼 수 있습니다. 3.12보다 낮으면 이 두 기능만 못 쓰고,
나머지 기능은 그대로 됩니다. 필요한 패키지는 한 줄로 설치합니다.

```
pip install pint uncertainties numpy scipy pandas pydoe
```

`python doctor.py`를 돌렸을 때 "Skill dependencies" 줄에 이 패키지 이름이 **WARN**으로 나와도 설치가 실패한 게 아닙니다.
"이 기능을 쓰려면 이 패키지가 더 필요하다"는 안내일 뿐이니, 그 기능을 쓸 때만 깔면 됩니다.

## 3. 첫 명령 내려보기

이제 진짜 시켜볼 차례입니다. 채팅창에 **한국어로 그냥 말하면** 됩니다.
명령어를 외울 필요 없습니다.

### 몸풀기 — 겁 안 나는 것부터

```
이 폴더에 어떤 파일들이 있는지 정리해서 알려줘.
```

AI가 폴더를 훑어보고 목록과 설명을 정리해줍니다.
**아무것도 고치지 않고 읽기만 하는 작업**이라 안전합니다. 감을 잡기 좋습니다.

### 이 툴킷의 진짜 기능 써보기

이 툴킷에는 논문 검색, 그래프 그리기, 통계, 문서 작업 같은 기능(스킬)이 들어있습니다.
예를 들어:

```
효소 반응속도(kinetics) 관련 최근 논문 5편만 찾아서 요약해줘.
```

```
이 엑셀 파일(파일명 알려주세요)로 막대그래프를 그려줘. 논문에 넣을 수 있는 스타일로.
```

AI가 알아서 적절한 기능을 골라 실행합니다. 여러분은 "무슨 스킬을 써야 하지?"를
고민할 필요가 없습니다 — 하고 싶은 걸 말로 하면 됩니다.

### 되돌아보기

AI가 뭔가 고치거나 만들기 전에는 대체로 **"이렇게 해도 될까요?"** 하고 물어봅니다.
(얼마나 자주 묻는지는 권한 모드에 따라 다릅니다. 아래 4번을 보세요.)
- 내용을 확인하고 괜찮으면 승인,
- 아니다 싶으면 거절하거나 다시 설명하면 됩니다.

처음엔 이 확인 단계를 켜두고 옆에서 지켜보세요. 익숙해지면 점점 맡기면 됩니다.

## 4. 권한 설정 — "허용" 창 다루기

AI가 파일을 고치거나 명령을 실행하기 전에 띄우는 확인 창이 **권한 요청**입니다.
처음 며칠은 이 창을 보면서 AI가 무엇을 하려는지 익히는 것이 가장 좋은 공부입니다.

### 허용 창이 뜨면

창에는 AI가 하려는 일(고칠 파일 이름, 실행할 명령)이 적혀 있고, 보통 이런 선택지가 나옵니다.

| 선택지 | 뜻 |
|---|---|
| **Yes** | 이번 한 번만 허용 |
| **Yes, and don't ask again for …** | 같은 종류의 작업은 앞으로 묻지 않음 |
| **No** | 거절. 거절한 뒤 "이건 왜 하려는 거야?"라고 물어도 됩니다 |

누르기 전에 세 가지만 보세요.

- **어느 파일인가**: 작업 폴더 밖의 파일이나 원본 데이터를 고치려 하면 일단 거절하고 이유를 물어보세요.
- **지우는 일인가**: `rm`, `del`, "삭제"가 보이면 한 번 더 읽어 보세요.
- **밖으로 내보내는 일인가**: `git push`, 메일 보내기, 업로드는 되돌리기 어렵습니다.

명령이 무슨 뜻인지 모르겠으면 **No**를 누르고 "방금 그 명령이 뭘 하는 거야?"라고 물어보세요.
설명을 듣고 다시 시키면 됩니다.

"다시 묻지 않기"는 종류에 따라 기억하는 기간이 다릅니다. 명령은 그 폴더에서 계속 기억하고,
파일 수정은 이번 대화가 끝날 때까지만 기억합니다. ([공식 설명](https://code.claude.com/docs/ko/permissions))

### 권한 모드 고르기

AI가 얼마나 자주 물어볼지는 **권한 모드**로 정합니다. 데스크톱 앱은 전송 버튼 옆의 모드 선택기,
VS Code는 입력창의 모드 표시기, 터미널은 `Shift+Tab`으로 바꿉니다.

| 모드 | 묻지 않고 하는 일 | 언제 쓰나 |
|---|---|---|
| **Manual** | 읽기만 | **처음엔 이것.** 모든 변경을 직접 확인 |
| **Accept edits** | 읽기, 파일 수정 | 익숙해진 뒤 반복 작업할 때. 다른 명령은 여전히 물어봄 |
| **Plan** | 읽기 (고치지 않고 계획만 제안) | 큰 작업 전에 "어떻게 할지"부터 보고 싶을 때 |
| **Auto** | 대부분 (다른 AI가 뒤에서 위험한 작업을 걸러냄) | 확인 창이 너무 잦아 귀찮을 때 |
| **Bypass permissions** | 전부 | **쓰지 마세요.** 격리된 테스트 환경 전용 |

최신 버전의 터미널과 VS Code는 **Auto로 시작**할 수 있어서 허용 창이 거의 뜨지 않을 수 있습니다.
처음에는 Manual로 바꿔 두고 지켜보세요. 데스크톱 앱은 폴더마다 마지막에 고른 모드를 기억합니다.
([권한 모드 공식 문서](https://code.claude.com/docs/ko/permission-modes))

### 자동 허용·금지 규칙 (선택)

같은 질문에 계속 "Yes"를 누르게 된다면 규칙으로 정해 둘 수 있습니다. 보통은 허용 창에서
"don't ask again"을 누르면 규칙이 저절로 저장되므로 직접 쓸 일은 많지 않습니다.
직접 쓰려면 작업 폴더의 `.claude/settings.json`(이 폴더만) 또는 `~/.claude/settings.json`(내 컴퓨터 전체)에 적습니다.

```json
{
  "permissions": {
    "allow": ["Bash(git diff *)", "Bash(git log *)"],
    "deny": ["Bash(git push *)", "Bash(rm -rf *)"]
  }
}
```

- `allow`: 묻지 않고 실행 (위 예시는 변경 내역 보기처럼 아무것도 바꾸지 않는 명령)
- `deny`: 시켜도 실행하지 않음 (위 예시는 인터넷에 올리기, 폴더 통째로 지우기)
- `*`는 "뒤에 무엇이 오든"이라는 뜻입니다. `Bash(python *)`처럼 넓게 허용하면 사실상
  아무 코드나 묻지 않고 돌아가니 피하세요.

규칙 문법과 설정 파일 위치는 [권한 구성](https://code.claude.com/docs/ko/permissions)과
[설정 파일](https://code.claude.com/docs/ko/settings) 공식 문서에 있습니다.

## 5. 자주 겪는 첫날 문제

| 증상 | 이렇게 해보세요 |
|---|---|
| 로그인이 안 돼요 | 구독 계정이 맞는지, Claude Pro/Max가 활성인지 확인. 그래도 안 되면 앱 재시작. |
| AI가 우리 실험실 스타일을 모르는 것 같아요 | 작업 폴더가 `sci-toolkit`으로 지정됐는지 확인 (2번 단계). |
| 뭘 물어봐도 "권한이 필요하다"고만 해요 | 그 요청을 승인(허용)해주면 진행됩니다. 내용이 이상하면 거절하세요. 확인할 점은 4번 참고. |
| 명령을 어떻게 써야 할지 모르겠어요 | 그냥 하고 싶은 걸 편하게 한국어로 적으세요. 애매하면 AI가 되물어봅니다. |

## 6. Codex 팁

[Codex](https://developers.openai.com/codex)(OpenAI의 비슷한 도구)를 쓰시는 경우에도 큰 그림은 같습니다.

- 설치: ChatGPT 구독(Plus 이상) 환경에서 Codex를 켜거나, 안내에 따라 CLI를 설치합니다.
- 이 툴킷을 얹기: `sci-toolkit` 폴더를 작업 폴더로 열면, Codex는 `AGENTS.md`를 자동으로 읽습니다.
  (Claude Code는 `AGENTS.md`를, Codex도 같은 `AGENTS.md`를 참고하도록 맞춰져 있습니다.)
- 첫 명령: 마찬가지로 한국어로 하고 싶은 걸 말하면 됩니다. 실행 방법만 조금 다를 뿐,
  "폴더 열고 → 말로 시키고 → 확인하고 승인" 흐름은 동일합니다.
