# 09. 원격 서버에서 쓰기 — 랩 공용 서버 · HPC · 클라우드

내 노트북이 아니라 **다른 컴퓨터에서** Claude Code를 돌리고 싶을 때 읽는 문서입니다.

이런 경우에 해당합니다.

- 랩 공용 계산 서버에 데이터가 있고, 그 서버에서 분석하고 싶다
- GPU가 필요한 작업(구조 예측, 대규모 fitting)을 서버에서 돌려야 한다
- 학교 HPC(클러스터)에 접속해서 쓴다
- 내 노트북을 꺼도 작업이 계속 돌아야 한다

> 랩 공용 서버·HPC 접속 정보(주소·계정·키)는 이 배포판에 들어 있지 않습니다.
> 소속 랩/전산실에서 받은 정보를 쓰세요. **접속 정보를 이 폴더 안에 저장하지 마세요.**

---

## 0. 먼저 확인할 것 — 정말 원격이 필요한가

원격은 편의보다 번거로움이 먼저 옵니다. 아래에 해당하면 그냥 **노트북에서** 하세요.

| 상황 | 권장 |
|---|---|
| 데이터가 내 노트북에 있고 몇 분이면 끝난다 | 로컬 |
| 엑셀·워드·그림 작업 | 로컬 (원격은 GUI가 불편) |
| 데이터가 서버에만 있다 / 용량이 크다 | 원격 |
| GPU가 필요하다 | 원격 |
| 몇 시간~며칠 걸린다 | 원격 (노트북 꺼도 계속 돎) |

---

## 1. 방법 A — VS Code Remote-SSH (가장 추천)

원격 서버의 파일을 **내 VS Code 화면에서 그대로** 열어 쓰는 방식입니다.
터미널만 쓰는 것보다 훨씬 편하고, Claude Code 익스텐션도 원격 쪽에서 그대로 돕니다.

1. VS Code 확장에서 **`Remote - SSH`** (Microsoft 제작)를 설치합니다.
2. `F1` → `Remote-SSH: Connect to Host...` → 서버 주소 입력
   (형식: `사용자이름@서버주소`, 예: `hong@server.example.ac.kr`)
3. 비밀번호 또는 SSH 키로 로그인합니다.
4. 접속되면 **새 창이 원격 서버에 붙은 상태**가 됩니다.
   여기서 폴더를 열고, Claude Code 익스텐션을 설치·로그인하면 끝입니다.

> 익스텐션은 **원격 쪽에 따로 설치**해야 할 수 있습니다.
> VS Code가 "Install in SSH: 서버명" 버튼을 보여주면 그걸 누르세요.

이 방식이 편한 이유는 파일 탐색·편집·터미널·Claude가 한 화면에 있다는 점입니다.
결과 그림을 그 자리에서 미리보기로 확인할 수 있습니다.

---

## 2. 방법 B — 터미널로 SSH 접속 후 CLI

VS Code를 안 쓰거나, 가벼운 작업만 할 때.

```bash
ssh 사용자이름@서버주소          # 서버 접속
cd /path/to/my/project          # 작업할 폴더로 이동
claude                          # Claude Code 실행
```

서버에 Claude Code가 없다면 먼저 설치합니다.

```bash
npm install -g @anthropic-ai/claude-code
```

`npm`이 없고 관리자 권한도 없다면, 전산 담당자에게 Node.js 설치를 요청하거나
[nodejs.org](https://nodejs.org) 안내에 따라 사용자 홈 디렉토리에 설치하세요.

### 이 툴킷을 서버에도 얹기

노트북에서 서버로 폴더를 복사합니다(노트북 터미널에서 실행).

```bash
scp -r sci-toolkit 사용자이름@서버주소:~/
```

복사가 끝나면 서버에서 `~/sci-toolkit` 폴더를 열고 쓰면 됩니다.
스킬만 골라 설치하려면 서버에서:

```bash
cd ~/sci-toolkit
python install/install.py --preset data-figures --apply
```

## 3. 긴 작업 — 접속이 끊겨도 계속 돌게 하기

SSH는 **연결이 끊기면 실행 중이던 것도 같이 죽습니다.** 노트북을 닫거나
와이파이가 끊기면 몇 시간 돌던 계산이 날아갑니다. 이걸 막는 방법입니다.

### tmux (권장)

```bash
tmux new -s work        # 'work'라는 이름의 세션 시작
# ... 여기서 claude 실행하고 작업 ...
# Ctrl+b 를 누른 뒤 d  → 세션에서 빠져나옴 (작업은 계속 돎)

tmux attach -t work     # 나중에 다시 접속해서 이어보기
tmux ls                 # 돌고 있는 세션 목록
```

노트북을 꺼도 서버에서는 계속 돕니다. 다음 날 다시 접속해 `tmux attach` 하면
그동안의 출력이 그대로 남아 있습니다.

### nohup (간단한 단발 작업)

```bash
nohup python my_analysis.py > run.log 2>&1 &
tail -f run.log         # 진행 상황 보기 (Ctrl+C 로 보기만 중단)
```

## 4. 결과 가져오기

서버에서 만든 그림·표·리포트를 노트북으로 가져올 때 (노트북 터미널에서 실행).

```bash
scp 사용자이름@서버주소:~/project/figure.png .        # 파일 하나
scp -r 사용자이름@서버주소:~/project/results ./       # 폴더 통째로
```

VS Code Remote-SSH를 쓴다면 파일 탐색기에서 **드래그로 끌어오면** 됩니다.

## 5. HPC(클러스터)에서 주의할 점

학교 HPC는 보통 **로그인 노드**와 **계산 노드**가 나뉘어 있습니다.

- **로그인 노드에서 무거운 계산을 돌리면 안 됩니다.** 다른 사용자에게 피해가 가고,
  관리자가 프로세스를 강제 종료할 수 있습니다.
- 무거운 작업은 **작업 스케줄러**(SLURM 등)에 제출해야 합니다.

```bash
sbatch my_job.sh        # SLURM에 작업 제출
squeue -u $USER         # 내 작업 상태 확인
```

Claude Code에게 "이 분석을 SLURM 작업 스크립트로 만들어줘"라고 시키면
`my_job.sh` 형태로 작성해 줍니다. 다만 **파티션 이름·시간 제한·자원 요청량은
학교마다 다르므로** 전산실 안내 문서를 함께 알려주세요.

계산 자원을 먼저 확인하고 싶다면 `get-available-resources` 스킬을 쓰면
CPU·GPU·메모리·디스크를 조사해 어떤 전략이 맞는지 알려줍니다.

## 6. 보안 — 꼭 지킬 것

- **접속 정보(주소·계정·비밀번호·SSH 키)를 이 툴킷 폴더 안에 저장하지 마세요.**
  이 폴더는 사람들 사이에 복사되어 돌아다닙니다.
- SSH 키는 `~/.ssh/` 에 두고, 비밀번호 대신 키를 쓰는 편이 안전합니다.
- 공용 서버에 **개인 API 키를 평문으로 두지 마세요.** 다른 사용자가 볼 수 있습니다.
  환경변수나 권한을 제한한 파일(`chmod 600`)을 쓰세요.
- 공용 서버의 공유 폴더에 **다른 사람 데이터가 섞여 있을 수 있습니다.**
  AI에게 폴더를 통째로 읽히기 전에 그 안에 뭐가 있는지 먼저 확인하세요.
- 랩 정책상 외부로 나가면 안 되는 데이터가 있는지 확인하세요.
  판단이 서지 않으면 지도교수·선배에게 먼저 물어보세요.

## 7. 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| `claude: command not found` | 서버에 설치가 안 됐거나 PATH에 없음. `npm install -g @anthropic-ai/claude-code` 후 재로그인 |
| 접속이 자꾸 끊긴다 | tmux를 쓰세요(3번). SSH 설정에 `ServerAliveInterval 60` 을 넣어도 도움이 됩니다 |
| 로그인이 매번 풀린다 | 서버에서 한 번 로그인하면 유지됩니다. 홈 디렉토리가 매번 초기화되는 환경이면 전산실에 문의 |
| 한글이 깨진다 | `export LANG=ko_KR.UTF-8` 또는 `LC_ALL=C.UTF-8` 을 `~/.bashrc` 에 추가 |
| 그림이 안 그려진다 | 서버에 화면이 없어서입니다. matplotlib에 `matplotlib.use("Agg")` 를 쓰고 파일로 저장하세요 |
| 느리다 | 큰 파일을 매번 전송 중일 수 있습니다. 작업 폴더를 서버 쪽에 두세요 |
