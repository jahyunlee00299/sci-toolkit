# 14. 터미널 읽기 좋게 만들기

로그가 뭉개져 보이고, 한글 표가 ASCII 헤더와 어긋나고, 동시에 띄운 탭이 전부
똑같이 생겨서 어느 게 실패한 건지 모르겠다면 — 이 문서가 그 셋을 고칩니다.

취향 문제가 아닙니다. 틀린 숫자를 발견하느냐 그냥 지나치느냐가 여기서 갈립니다.

```bash
python scripts/terminal_setup.py            # 미리보기 (아무것도 안 씀)
python scripts/terminal_setup.py --apply    # 백업 후 적용
python scripts/terminal_setup.py --verify   # 실제로 먹었는지 확인
python scripts/terminal_setup.py --revert   # 되돌리기
```

`--apply` 없이는 **아무것도 쓰지 않습니다.** 건드리는 파일은 전부 시각이 찍힌
`.bak` 으로 먼저 복사하고, `--revert` 로 되돌립니다.

## 무엇이 바뀌나

| | 내용 |
|---|---|
| 색 스킴 | Catppuccin Mocha — `schemes` 에 정의하고 프로필에 적용 |
| 폰트 | 설치된 것 중 최선 (D2Coding → Cascadia → Consolas) |
| 탭 색 | 프로필 종류별로 다른 색 (PowerShell·cmd·WSL·SSH…) |
| 가독성 | 대비 자동 보정, 굵은 글씨 구분, 커서 모양 |
| 히스토리 | PowerShell = PSReadLine 예측 / bash = `.inputrc` 접두어 검색 |

이미 값이 있으면 **덮어쓰지 않습니다.** 직접 색을 골라둔 프로필은 그대로 둡니다.

## WSL 을 쓴다면 — 절반은 이미 끝나 있습니다

WSL 창을 그리는 건 Linux 가 아니라 **Windows Terminal** 입니다.

그래서 색 스킴·폰트·탭 색은 Windows 쪽 설정을 **그대로 물려받습니다.**
Linux 에 폰트를 깔 필요도, 스킴을 따로 만들 필요도 없습니다. Windows 에서 한 번
적용하면 WSL 탭도 같이 예뻐집니다.

bash 에 진짜로 없는 건 **히스토리 예측** 하나뿐이고, 그래서 Linux 쪽에서 이
스크립트가 만드는 건 `~/.inputrc` 딱 하나입니다.

```
# .inputrc 가 하는 일
명령어 앞부분을 치고 ↑ 를 누르면 → 그 접두어로 시작하는 기록만 훑습니다
```

bash 에는 PSReadLine 같은 회색 미리보기 글씨가 없습니다. 접두어 검색이 가장
가까운 대체물입니다.

---

## 조용히 실패하는 두 가지 (이 스크립트가 막는 것)

### 1. 없는 이름을 써도 아무 말이 없습니다

Windows Terminal 은 이런 걸 순순히 받아들입니다.

```jsonc
"colorScheme": "Dark+"                    // schemes 에 Dark+ 가 없어도 OK
"font": { "face": "D2Coding Nerd Font" }  // 그런 폰트가 없어도 OK
```

경고도, 로그도 없습니다. 그냥 기본값으로 그리고, 사용자 눈에는 "설정이 안 먹었네"
로만 보입니다. 실제로 이 저장소 작성 중 두 개 다 겪었습니다.

그래서 이 스크립트는

- 정의하지 않은 스킴 이름은 **쓰지 않고**
- 폰트는 OS 에 "그 이름 있냐" 물어본 **뒤에만** 씁니다
- `--verify` 가 이 둘을 다시 확인합니다

> **폰트 이름 함정**: 내려받는 이름과 OS 가 부르는 이름이 다릅니다.
> `D2Coding Nerd Font` 가 아니라 **`D2Coding ligature`** 입니다.
> 확인: `python scripts/terminal_setup.py --verify`

### 2. PowerShell 5.1 은 절반만 됩니다

| | 5.1 | 7.1+ |
|---|---|---|
| 히스토리 예측 | 됨 | 됨 |
| 플러그인 예측 (AI식 제안) | **안 됨** | 됨 |
| ListView | PSReadLine 2.2.6+ 필요 | 같음 |

5.1 은 PSReadLine **2.0.0** 이 딸려오고 스스로 갱신하지 않습니다. ListView 를
쓰려면 모듈을 올려야 합니다.

```powershell
# NuGet 을 먼저 깔아야 합니다 — 안 그러면 Install-Module 이
# "공급자 설치할까요?" 프롬프트에서 아무 출력 없이 멈춥니다
Install-PackageProvider -Name NuGet -MinimumVersion 2.8.5.201 -Scope CurrentUser -Force
Install-Module PSReadLine -Scope CurrentUser -Force -SkipPublisherCheck
```

이 스크립트가 넣는 프로필 블록은 버전이 낮으면 **알아서 ListView 를 끄고** 나머지만
적용합니다. 오류를 내지 않습니다.

## 프로필이 오류를 뱉는다면

스크립트 실행 때마다 빨간 글씨가 뜬다면 예측 설정이 원인입니다.

파이프로 실행되는 셸(=모든 스크립트와 훅)에는 콘솔 버퍼가 없어서
`PredictionSource` 와 `PredictionViewStyle` **둘 다** 예외를 던집니다.

이 스크립트가 넣는 블록은 진짜 콘솔인지 먼저 확인하고 들어갑니다.

```powershell
try {
    $null = $Host.UI.RawUI.KeyAvailable   # 리다이렉트면 여기서 예외
    Set-PSReadLineOption -PredictionSource History
    Set-PSReadLineOption -PredictionViewStyle ListView
} catch { }
```

직접 프로필을 손봤다면 같은 가드를 쓰세요.

## 탭이 많을 때 구분하기

프로필별 색은 **어느 셸인지**를 알려줍니다. 같은 셸로 띄운 세션 여러 개를 구분하려면
실행할 때 색을 얹으면 됩니다.

```powershell
wt -w 0 new-tab -p "Windows PowerShell" --tabColor "#89B4FA" --title "run-3"
```

`--tabColor` 는 프로필 값을 덮어씁니다. 자동화 스크립트가 세션마다 팔레트를
돌려가며 주면, **어느 셸 × 어느 실행** 두 축이 한눈에 들어옵니다.

> PowerShell 에서 `wt` 인자에 `;` 가 들어가면 명령 구분자로 먹힙니다. 백틱으로
> 이스케이프하세요. 창을 나눴다면 나누는 하위 명령(wt 의 split-pane)에도 `--tabColor` 를
> 따로 줘야 첫 창 말고도 색이 붙습니다.

## 한글이 깨지거나 표가 어긋난다면

- **폭이 어긋남** → D2Coding 계열을 쓰세요. 한글이 라틴의 정확히 2배 폭으로
  설계돼서 표가 맞습니다. Cascadia·JetBrains Mono 에는 한글이 아예 없어 시스템
  폰트로 폴백되고, 그 지점에서 폭이 깨집니다.
  설치: https://github.com/naver/d2-coding-font
- **그래도 깨짐** → Windows Terminal 에 한글 렌더링 미해결 이슈가 있습니다
  ([microsoft/terminal#16778](https://github.com/microsoft/terminal/issues/16778)).
  폭 계산 문제라 폰트만으로 완전히 피하긴 어렵습니다.
- **`.ps1` 안의 한글이 깨짐** → PowerShell 5.1 은 BOM 없는 `.ps1` 을 ANSI 코드페이지로
  읽습니다. **UTF-8 with BOM** 으로 저장하세요.

원본 옆에 있으니 직접 복사해도 됩니다.
