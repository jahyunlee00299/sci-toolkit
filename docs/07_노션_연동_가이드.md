# 07. 노션(Notion) 연동 가이드 — 내 할 일/프로젝트 DB를 AI에게 읽히기

> 한 줄 요약: **읽기는 자유롭게, 새 항목 추가는 --write 를 붙였을 때만, 삭제 기능은 아예 없습니다.**

이 문서는 `scripts/connectors/notion_db_connector.py` 를 이용해 노션의 **데이터베이스(DB)**를
AI에게 읽히고, 새 항목을 초안처럼 추가하는 방법을 초심자 눈높이에서 설명합니다.
연결·보안의 큰 원칙은 [05_외부서비스_연동](05_외부서비스_연동.md)에서 이미 다뤘으니, 이 문서는
"노션 DB" 케이스에 집중합니다.

---

## 1. 노션 연동이 뭘 해주나요?

노션에 "할 일" 목록이나 "프로젝트" 목록을 데이터베이스(표처럼 생긴 것)로 관리하고 있다면,
이 연동으로 AI가 할 수 있는 일은 두 가지입니다.

1. **읽기**: "지금 진행 중인 할 일이 뭐가 있지?" 를 AI가 노션 DB에서 직접 조회해서 알려줍니다.
2. **추가(초안처럼)**: "이 할 일 하나 추가해줘" 하면 AI가 새 항목을 만들어줍니다. 단, 이 동작은
   기본적으로 **미리보기만** 하고, 실제로 추가하려면 `--write` 라는 플래그를 명시적으로 붙여야 합니다.
   (05번 문서의 "나가는 건 초안까지만" 원칙과 같은 결입니다 — 되돌리기 어려운 동작은 한 번 더 확인.)

이 스크립트에는 **삭제 기능이 아예 없습니다.** 실수로 지워질 걱정 없이 안심하고 읽기/추가만
시켜볼 수 있습니다.

---

## 2. 준비 1 — 노션 Integration 만들고 토큰 발급받기

노션 API를 쓰려면 "Integration"이라는 걸 하나 만들어야 합니다. `docs/02_API와_MCP.md`의
비유를 그대로 쓰면, **Integration = 출입증을 발급받는 창구**입니다.

1. 브라우저에서 `notion.so/my-integrations` 로 이동합니다.
2. "New integration"(새 통합)을 눌러 이름을 하나 붙입니다 (예: "sci-toolkit-connector" 등 알아보기 쉬운 이름).
3. 생성하면 "Internal Integration Token"(비밀 토큰 문자열)이 나옵니다. 이게 **출입증**입니다.
4. 이 토큰을 아래 둘 중 하나로 등록합니다.
   - `config/credentials.json` 의 `notion.token` 자리에 붙여넣기 (이 파일은 배포·커밋에서 제외됩니다), 또는
   - 환경변수 `SCITK_NOTION_TOKEN` 을 설정하고, `credentials.json` 에는 `"token": "ENV:SCITK_NOTION_TOKEN"` 처럼 적어두기 (토큰 값 자체가 파일에 안 남아 더 안전).

> 토큰을 채팅창에 그대로 붙여넣지 마세요. 05번 문서의 "토큰 = 출입증" 원칙 그대로입니다.

---

## 3. 준비 2 (⭐ 가장 흔한 함정) — Integration을 대상 DB에 공유하기

Integration을 만들고 토큰까지 등록했는데도 `list-dbs` 를 실행하면 **아무것도 안 뜨는 경우**가
정말 많습니다. 이유는 하나입니다.

> **노션 Integration은 기본적으로 "아무 DB도 못 봅니다."** 여러분이 보고 싶은 DB마다
> 일일이 "이 Integration이 여길 봐도 돼" 라고 공유(Connections)해줘야 합니다.

방법은 이렇습니다.

1. 노션에서 연결하고 싶은 데이터베이스 페이지를 엽니다.
2. 우측 상단의 **"..."** (더보기) 메뉴를 클릭합니다.
3. **"연결(Connections)"** 항목을 찾아 클릭합니다.
4. 방금 만든 Integration 이름을 검색해서 선택합니다.

이 과정을 건너뛰면:
- `list-dbs` 목록에 그 DB가 아예 안 보이고,
- `schema`/`query`/`add-row` 를 그 DB의 id로 직접 시도해도 **404 오류**가 납니다.

스크립트도 이 오류가 나면 "Integration이 공유됐는지 확인하세요"라고 안내 메시지를 띄우도록
만들어져 있습니다. 404나 403이 뜨면 제일 먼저 이 단계를 의심하세요.

---

## 4. DB ID(아이디) 찾는 법

노션 데이터베이스를 브라우저에서 열면 주소창에 이런 식의 URL이 보입니다.

```
https://www.notion.so/워크스페이스이름/<32자리-영숫자>?v=...
```

이 `<32자리 영숫자>` 부분이 데이터베이스 ID입니다. 하이픈(-)이 섞여 있어도 그대로 복사해서
쓰면 됩니다. 이 ID를 `--db` 인자에 넣습니다.

> 팁: 어떤 DB의 ID를 모르겠으면, 먼저 `list-dbs` 를 실행해서 이름과 함께 id를 확인하세요
> (단, 2단계의 "공유"를 먼저 해야 목록에 보입니다).

---

## 5. 기본 사용법

모든 명령은 toolkit 루트에서 실행합니다.

```bash
# 1) 내가 볼 수 있는(=공유받은) 데이터베이스 목록 [READ]
python scripts/connectors/notion_db_connector.py list-dbs

# 2) 특정 DB의 속성(스키마) 확인 — 어떤 필드가 있는지, 타입이 뭔지 [READ]
python scripts/connectors/notion_db_connector.py schema --db <YOUR_DATABASE_ID>

# 3) DB의 행(항목) 조회, 최근 10개 [READ]
python scripts/connectors/notion_db_connector.py query --db <YOUR_DATABASE_ID>

# 3-1) 상태값으로 간단 필터링
python scripts/connectors/notion_db_connector.py query --db <YOUR_DATABASE_ID> --status "In progress"

# 4) 새 항목 추가 — 먼저 --write 없이 미리보기(dry-run)
python scripts/connectors/notion_db_connector.py add-row --db <YOUR_DATABASE_ID> --title "예시 항목" --prop Status="In progress"

# 4-1) 실제로 추가하려면 --write 를 붙인다
python scripts/connectors/notion_db_connector.py add-row --db <YOUR_DATABASE_ID> --title "예시 항목" --prop Status="In progress" --write
```

`--prop NAME=VALUE` 는 여러 번 반복해서 여러 속성을 한 번에 채울 수 있습니다.

```bash
python scripts/connectors/notion_db_connector.py add-row \
  --db <YOUR_DATABASE_ID> \
  --title "예시 항목" \
  --prop Status="In progress" \
  --prop Tags="urgent,review" \
  --write
```

> `add-row` 는 실행되기 전에 항상 먼저 그 DB의 스키마(`schema`)를 내부적으로 조회해서,
> 여러분이 지정한 속성 이름이 실제로 존재하는지, 어떤 타입인지 확인한 뒤 알맞은 형태로
> 값을 보냅니다. 존재하지 않는 속성명을 쓰면 "이런 속성이 없습니다, 사용 가능한 속성:
> ..." 라는 오류로 바로 알려줍니다.

## 6. ⭐ 안전 요약

| 동작 | 기본 동작 | 되돌릴 수 있나 |
|---|---|---|
| `list-dbs` / `schema` / `query` | 바로 실행 (읽기 전용) | 원래 아무것도 안 바꾸는 동작 |
| `add-row` (`--write` 없이) | 미리보기만 출력, 실제로 아무 일도 안 일어남 | — |
| `add-row --write` | 실제로 새 항목 생성 | 노션에서 수동으로 지우면 되돌릴 수 있음 |
| (삭제/보관) | **이 스크립트엔 아예 없음** | — |

- 읽기(`list-dbs`/`schema`/`query`)는 언제든 자유롭게 실행해도 됩니다.
- 항목 추가(`add-row`)는 `--write` 를 붙이지 않으면 무엇이 생성될지 미리 보여주기만 합니다.
- **남도 같이 보는 DB**(팀 공유 DB)에 추가하는 경우라면, `--write` 를 붙이기 전에 미리보기
  내용을 한 번 더 확인하는 걸 권장합니다 — 05번 문서의 "남에게 영향을 주는 동작은 확인받기"
  원칙과 같습니다.
- 이 스크립트로는 항목을 지우거나 보관 처리할 수 없습니다. 지우는 작업이 필요하면 노션에서
  직접 수행하세요 (의도적인 설계입니다).

## 7. 노션 데이터베이스의 일반적인 속성 타입

노션 DB는 어떤 프로젝트/랩이든 대체로 비슷한 모양의 속성(컬럼) 타입을 씁니다. 아래는
**타입 자체에 대한 일반적인 설명**입니다(특정 랩의 실제 값이 아닙니다).

| 속성 타입 | 뜻 | 예시로 보는 형태 |
|---|---|---|
| `title` | 항목의 제목. 모든 DB에 정확히 하나만 있음 | "실험 결과 정리하기" |
| `status` | 진행 상태(단계형). 보통 "시작 전 / 진행 중 / 완료" 같은 몇 단계로 구성 | Not started / In progress / Done |
| `select` | 단일 선택 목록 (분류용) | 하나의 카테고리 값 선택 |
| `multi_select` | 다중 선택 목록 (태그처럼 여러 개 동시 선택 가능) | 태그 여러 개 |
| `person` | 담당자/관련 인물 지정 (노션 워크스페이스 멤버) | 담당자 1명 이상 |
| `date` | 날짜 또는 날짜 범위 | 마감일, 시작일 |
| `number` | 숫자 값 (예: 진행률 %) | 0~100 사이 숫자 |
| `relation` | 다른 데이터베이스의 항목과 연결 (예: "할 일" DB ↔ "프로젝트" DB) | 항목 간 참조 |
| `rich_text` | 일반 텍스트(서식 포함 가능) | 메모, 설명 |
| `checkbox` | 참/거짓 체크박스 | 완료 여부 체크 |

예를 들어 "할 일 관리용" DB라면 보통 title(제목) + status(상태) + select(종류) +
multi_select(태그) + person(담당자) + date(날짜) + relation(프로젝트 DB와 연결) 조합으로
구성되고, "프로젝트 관리용" DB라면 title + status + select(기간 단위: 주/월/분기 등) +
number(진행률 %) + relation(할 일 DB와 연결) 조합으로 구성되는 식입니다. 실제로 어떤 속성이
있는지는 랩/프로젝트마다 다르므로, 반드시 `schema --db <id>` 로 직접 확인하세요 — 추측해서
`--prop` 이름을 넣으면 오류로 걸러집니다.

## 8. 문제가 생겼을 때 체크리스트

1. **401 오류** → 토큰이 잘못됐거나 안 채워짐. `config/credentials.json` 의 `notion.token` 또는
   환경변수를 다시 확인하세요.
2. **403/404 오류** → 거의 항상 "3장. Integration을 대상 DB에 공유"를 빠뜨린 경우입니다.
   노션에서 해당 DB 페이지의 "..." → 연결 → Integration 선택을 다시 확인하세요.
3. **400 오류 (add-row)** → 속성 이름 또는 타입이 실제 DB와 다릅니다. 먼저
   `schema --db <id>` 로 정확한 속성명·타입을 확인한 뒤 `--prop` 값을 맞춰서 다시 시도하세요.
4. **list-dbs 결과가 비어있음** → 아직 어떤 DB도 공유하지 않은 상태입니다. 3장을 따라 최소
   하나의 DB를 공유해보세요.

---

## 9. 한 줄 요약

- 노션 DB 연동 = **읽기(list-dbs/schema/query)는 자유, 추가(add-row)는 `--write` 필요, 삭제는 아예 없음.**
- 가장 흔한 실수 = 토큰만 발급받고 **대상 DB에 Integration을 공유(Connections)하는 걸 빠뜨리는 것.**
- 속성 이름이 헷갈리면 무조건 `schema --db <id>` 부터 먼저 실행하세요.
