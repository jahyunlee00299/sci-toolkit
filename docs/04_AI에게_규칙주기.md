# 04. AI에게 규칙 주기 — CLAUDE.md / AGENTS.md가 뭔가요

이 문서는 **"왜 AI 에이전트한테 규칙 파일 같은 걸 만들어줘야 하지?"** 라는
의문이 드는 초심자를 위한 안내문입니다. 개념만 이해하면 되고, 지금 당장
직접 규칙 파일을 쓰실 필요는 없습니다.

---

## 1. 규칙 파일이 왜 필요한가요?

00번 문서에서 AI 에이전트를 "내 컴퓨터 앞에 앉혀놓은 신입 연구원"에
비유했습니다. 신입 연구원이 출근 첫날 아무 설명도 없이 일을 시작하면
어떻게 될까요?

- 우리 실험실 파일 정리 방식을 몰라서 엉뚱한 곳에 저장하고,
- 중요한 원본 파일을 실수로 덮어쓸 수도 있고,
- 매번 "이건 이렇게 해주세요"를 처음부터 다시 설명해야 합니다.

**규칙 파일(CLAUDE.md / AGENTS.md)**은 이 신입 연구원에게 "우리 실험실은
이렇게 일한다"를 미리 적어서 책상 위에 놓아두는 것과 같습니다. AI는 작업을
시작하기 전에 이 파일을 자동으로 읽고, 그 안에 적힌 규칙을 따르려고
합니다.

> 비유: 회사의 "신입 사원 매뉴얼"이나 실험실의 "SOP(표준작업절차서)"와
> 같은 역할입니다. 사람이 매번 구두로 알려주지 않아도, 글로 적어두면
> 매번 지켜집니다.

---

## 2. CLAUDE.md와 AGENTS.md, 뭐가 다른가요?

- **CLAUDE.md** — Claude Code가 프로젝트 폴더에서 자동으로 읽는 파일
  이름입니다. Claude Code를 쓰신다면 이 이름으로 저장하면 됩니다.
- **AGENTS.md** — Claude Code뿐 아니라 Codex 등 다른 AI 에이전트 도구도
  공통으로 알아보는 이름입니다. 특정 도구에 종속되지 않은 "공용 규칙"을
  적을 때 씁니다.

같은 프로젝트에 두 파일을 같이 둘 수도 있습니다. 예를 들어 `CLAUDE.md`는
짧게 "자세한 내용은 AGENTS.md를 봐" 라고만 적고, 실제 내용은 `AGENTS.md`에
몰아서 적는 식입니다. 이 둘을 도구마다 따로 유지하기 번거로우니, 내용은
한 곳에 모아두고 다른 파일은 그쪽을 가리키게 하는 게 편합니다.

**어디에 두나요?** 보통 프로젝트 폴더(작업 중인 저장소)의 맨 위, 즉
루트 디렉터리에 둡니다. AI가 그 폴더에서 작업을 시작할 때 자동으로 찾아
읽습니다.

---

## 3. 규칙을 세 단계로 나누어 생각하기

규칙을 아무렇게나 나열하면 AI도, 사람도 헷갈립니다. 다음 세 단계로
나누어 생각하면 정리가 쉽습니다.

### ① 항상 지킬 것 (기본 원칙)

특별한 사정이 없는 한 매번 자동으로 지켜야 하는 것들입니다. 예:
"새 코드는 함수 단위로 작게 나눠서 작성한다", "중요한 계산 결과는
원본 데이터에서 다시 확인한다" 같은 것들이죠. 이런 건 AI가 매번 사람에게
물어볼 필요 없이 그냥 지키면 됩니다.

### ② 물어볼 것 (되돌리기 어렵거나 애매한 일)

"이대로 진행해도 되나요?" 하고 사람에게 먼저 확인받아야 하는 것들입니다.
보통 다음 두 가지 성격을 가집니다.

- **되돌리기 어려운 일** — 파일을 완전히 지운다, 백업 없이 덮어쓴다 등.
- **기본값이 애매한 일** — 여러 선택지가 있는데 어느 쪽이 맞는지 AI 혼자
  판단하기 어려운 경우.

### ③ 절대 안 되는 것 (금지 사항)

어떤 지시가 있어도, 심지어 "괜찮으니까 그냥 해줘"라는 말을 들어도 하면
안 되는 것들입니다. 예: 비밀번호나 API 키를 코드에 그대로 적어서
저장소에 올리는 것, 강제로 되돌릴 수 없는 삭제 명령을 확인 없이
실행하는 것 등이죠. 이 단계는 "웬만하면"이 아니라 "무조건"입니다.

> 이 세 단계로 나누어 적어두면, AI가 "이건 그냥 하면 되는 일이구나",
> "이건 먼저 물어봐야겠다", "이건 아예 하면 안 되는 일이구나"를 스스로
> 구분할 수 있게 됩니다.

## 4. 아주 작은 예시 (일반적인 내용만)

아래는 **어느 프로젝트에나 적용할 수 있는 아주 작고 일반적인 예시**입니다.
특정 연구실이나 개인 정보가 담긴 내용이 아니라, 개념을 보여주기 위한
샘플입니다. 실제로 복사해서 그대로 쓰셔도 되고, 우리 상황에 맞게 고쳐도
됩니다.

```markdown
# CLAUDE.md 예시

## 항상 지킬 것
- 코드를 고치기 전에 해당 파일을 먼저 읽고 시작한다 (추측하지 않는다).
- 새 코드는 한 가지 역할만 하도록 작게 나눠서 작성한다.
- 결과 숫자(계산값, 통계치 등)는 원본 데이터에서 다시 확인한 뒤 보고한다.

## 물어볼 것
- 기존 파일을 완전히 덮어써야 할 때 (백업이 없는 경우).
- 여러 방식 중 어느 쪽이 맞는지 판단하기 애매할 때.
- 외부로 나가는 행동(메일 발송, 공개 게시 등)을 하기 전.

## 절대 안 되는 것
- 비밀번호, API 키 등 민감 정보를 코드나 저장소에 그대로 올리는 것.
- 사용자의 명시적 요청 없이 파일을 강제로 삭제하거나
  되돌릴 수 없는 명령(`강제 삭제` 계열)을 실행하는 것.
- 확인 없이 중요 원본 파일을 실수로 덮어쓰는 것.
```

이렇게 세 줄짜리 섹션만 있어도 이미 꽤 쓸모가 있습니다. 처음부터 완벽하게
쓰려 하지 마시고, 일하면서 "아, 이건 미리 말해뒀어야 했는데" 싶은 게
생길 때마다 한 줄씩 추가해나가면 됩니다.

## 5. 이 툴킷은 이미 규칙 파일을 갖고 있습니다

지금 여러분이 쓰고 계신 이 sci-toolkit도 이미 이런 규칙 파일을 갖고
있습니다.

- **`AGENTS.md`** (툴킷 최상위 폴더) — 어떤 AI 에이전트 도구를 쓰든
  공통으로 적용되는 일반 규칙이 정리되어 있습니다. 요청이 들어왔을 때
  어떤 순서로 처리해야 하는지(라우팅 표), 코드 품질 원칙, 결과 검증
  원칙, 안전 기준(절대 안 되는 것 목록) 등이 담겨 있습니다.
- **`CLAUDE.md`** (같은 위치) — Claude Code용으로, `AGENTS.md`를
  가리키면서 몇 가지 Claude Code 전용 사항만 덧붙인 짧은 파일입니다.

지금 당장 이 파일들을 직접 편집하실 필요는 없습니다. 다만 "AI가 왜
이런 식으로 동작하지?"가 궁금해지실 때, 이 두 파일을 열어보시면 그
이유(어떤 규칙을 따르고 있는지)를 확인하실 수 있습니다. 특히
`AGENTS.md` 맨 앞의 "0. Routing" 표는 어떤 요청이 어떤 절차를 거치는지
한눈에 보여주므로, 궁금하실 때 훑어보시면 도움이 됩니다.

새 프로젝트를 시작할 때 규칙 파일이 필요하다면, `AGENTS.md`를 그대로
복사해서 시작하고 우리 상황에 맞게 고쳐 쓰는 방법도 있습니다 — 그 파일
맨 위에 "개인정보·기관명 없이 일반적으로 쓸 수 있도록 작성했다"고 적혀
있는 이유가 그것입니다.

## 6. 요약

| 질문 | 답 |
|---|---|
| 규칙 파일이 뭔가요? | AI 에이전트가 작업 전 자동으로 읽는, "우리는 이렇게 일한다"를 적은 문서 |
| CLAUDE.md vs AGENTS.md | 전자는 Claude Code 전용 이름, 후자는 도구 공통 이름. 같이 두고 내용은 한쪽에 몰아써도 됨 |
| 세 단계 규칙 | ① 항상 지킬 것 ② 물어볼 것(되돌리기 어렵거나 애매함) ③ 절대 안 되는 것 |
| 이 툴킷의 규칙 파일은? | 최상위 폴더의 `AGENTS.md`(공용 규칙) + `CLAUDE.md`(Claude Code용 짧은 안내) |
| 지금 당장 뭘 해야 하나요? | 아무것도 안 하셔도 됩니다. 궁금할 때 두 파일을 열어보시면 됩니다 |
