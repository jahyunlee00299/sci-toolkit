# 10. 전체 워크플로우 지도 — 이 툴킷이 실제로 어떻게 돌아가는가

앞 문서들이 "어떻게 설치하고 시작하는가"였다면, 이 문서는 **"내 작업이 어떤 경로를 타는가"**입니다.
구조를 한 번 파악해 두면, AI가 엉뚱한 길로 갈 때 바로 알아챌 수 있습니다.

---

## 1. 세 개의 층

이 패키지는 세 층으로 되어 있습니다. 역할이 다르니 섞어서 보지 마세요.

```
① 규칙       AGENTS.md  ─ AI가 따르는 운영 규칙. §0에 "요청 → 경로" 표가 있다.
                CLAUDE.md ─ Claude Code용 요약본 (같은 내용의 짧은 버전)
      ↓  (AI가 읽고 판단)
② 스킬       skills/<이름>/SKILL.md ─ 작업 종류별 "이럴 땐 이렇게" 지침서
                skills/<이름>/scripts/  ─ 그 스킬이 쓰는 실제 도구
      ↓  (지침에 따라 실행)
③ 검증       doctor.py, tests/, 각 스킬의 lint/check 스크립트
                ─ "다 됐다"고 말하기 전에 통과해야 하는 관문
```

**핵심**: ①이 경로를 정하고, ②가 일을 하고, **③이 통과해야 끝난 것**입니다.
③ 없이 "완료"라고 하는 건 이 툴킷에서 완료가 아닙니다.

---

## 2. 요청이 들어오면 무슨 일이 일어나는가

예를 들어 "이 원고 그림 번호 좀 봐줘"라고 했다면:

```
사용자 요청
    ↓
AGENTS.md §0 라우팅 표에서 해당 행을 찾는다
    → "그림/표 번호·캡션 확인" 행
    ↓
지정된 도구 실행
    → docx/scripts/figure_caption_check.py
    → docx/scripts/manuscript_ref_order.py
    ↓
🔒 게이트: 결과의 "종류"를 읽는다
    → "번호순 위반"이 곧 "캡션을 옮겨라"가 아니다.
      인용이 아예 없는 것 / 캡션 없는 유령 인용 / 초안 상태는 각각 다른 처방이다.
    ↓
사용자에게 보고 (근거와 함께)
```

AI가 이 경로를 벗어나 "그냥 파일 읽고 눈으로 봤다"고 하면 **잘못 가고 있는 것**입니다.
그럴 땐 "AGENTS.md §0의 경로대로 해줘"라고 하시면 됩니다.

---

## 3. 작업 유형별 경로 (요약)

전체 표는 `AGENTS.md` §0에 있습니다. 자주 쓰는 것만 추립니다.

| 하려는 일 | 쓰는 것 | 끝내기 전 통과해야 할 것 |
|---|---|---|
| 논문 찾기 | `research-search` | 🔒 `scripts/doi_verify.py` — 지어낸 DOI·철회 논문을 실제로 잡는다 |
| 참고문헌 + OA PDF 수집 | `scripts/ref_fetch.py` | 🔒 리포트의 불일치·미발견 항목을 그대로 보고 |
| 원고 쓰기·고치기 | `manuscript-pipeline` | 🔒 용어 lint + 수치 일관성 + `body_typo_lint.py`(단위·표기) |
| **워드 파일 편집** | `docx` → `incremental_edit.py` | 🔒 출력 파일에 `docx_preflight.py` + `word_validate.py` |
| **열어둔 워드 실시간 편집** | `docx` → `word_live_edit.py` | 편집 후 그 부분을 다시 읽어 확인 |
| 워드에서 글자 뽑기 | 🔒 `manuscript_text.py --count-only` **먼저** | 변경내용 추적이 있으면 일반 방식은 글을 흘린다 |
| 인용 넣기 | `endnote-citation-injection` | 🔒 `doi_verify.py --bibtex` + `endnote_biblio_check.py` |
| 그림 만들기 | `publication-figures` | 🔒 `figure_lint.py` + 숫자는 raw data에서 다시 |
| 데이터 분석 | `lab-data-analysis` → `stats-workflow` | 🔒 `assumption_check.py` — 정규성·등분산을 검사해 쓸 검정을 지목 |
| 모델 fitting·최적화 | 해당 스킬 → `scientific-validation` | 🔒 `sci_validate.py` (질량보존·물리적 타당성) |
| **문서에 숫자 넣기** | — | 🔒 원본 스크립트/raw data에서 다시 계산 |
| 메일·이슈·태스크 보내기 | `scripts/connectors/` | 🔒 **초안까지만.** 보내는 건 사람이 |
| 설치가 안 돼요 | `doctor.py` | 🔒 `PASS` 나올 때까지 |

🔒 = 스크립트로 강제되는 관문. 눈으로 판단하지 말고 실행해서 종료 코드를 보세요.

## 4. 왜 어떤 건 스크립트이고 어떤 건 문서인가

기준은 **"규칙으로 적을 수 있는가"**입니다. 되돌리기 쉬운 실수라도,
검사를 확실히 짤 수 있다면 스크립트로 만듭니다.

| | 스크립트로 강제 | 문서(가이드)로 안내 |
|---|---|---|
| **기준** | 판정 규칙이 명확해서 기계가 대신 볼 수 있음 | 상황 판단이 필요해서 규칙으로 못 줄임 |
| **예** | 원고 숫자·워드 손상·시크릿·DOI 실재성·통계 가정·용어 표기 | 어떤 DB로 검색할지, 어떤 논지를 세울지, 결과 해석 |
| **왜** | 사람도 AI도 "확인했다"고 착각한다. 스크립트는 지치지 않는다 | 기계가 대신 판단하면 오히려 틀린다 |

처음에는 "실수 비용이 낮으면 문서로 충분하다"고 봤지만, 그 기준으로 남겨둔 것들
대부분이 **사실은 기계 검사가 가능했습니다.** 그래서 다음 셋은 문서에서 스크립트로 옮겼습니다.

- **DOI 실재성** (`scripts/doi_verify.py`) — 지어낸 DOI는 사람 눈으로 구분되지 않습니다.
  CrossRef·OpenAlex 양쪽에 실제로 물어봐야 알 수 있고, 그건 기계가 훨씬 잘합니다.
- **통계 가정** (`stats-workflow/scripts/assumption_check.py`) — "정규분포처럼 보인다"는
  판단은 자주 틀립니다. Shapiro-Wilk와 Levene을 돌리고 그 결과로 검정을 고르는 건
  완전히 기계적인 절차입니다.
- **용어·단위 표기** (`manuscript-pipeline/scripts/body_typo_lint.py`) —
  `50ul`, `n=3`, `NAD+` 같은 건 규칙이 명확합니다. 눈으로 훑는 것보다 정확합니다.

반대로 **"이 결과를 어떻게 해석할지"**는 계속 문서로 둡니다. 규칙으로 줄이면
오히려 틀린 답을 강요하게 되기 때문입니다.

> 판단이 서지 않을 때: **"이 규칙을 남이 그대로 따라 할 수 있게 적을 수 있나?"**
> 적을 수 있으면 스크립트로 만드는 게 낫습니다.

## 5. 스스로 점검하기

```bash
python doctor.py                        # 이거 하나면 아래를 전부 자동 실행한다
```

`doctor.py` 가 돌리는 것:

| 검사 | 무엇을 보는가 |
|---|---|
| SHA256SUMS | USB 복사 중 파일이 깨졌는지 |
| SENTINEL | 시크릿·개인정보가 섞여 들어갔는지 |
| `test_skill_references.py` | 문서가 없는 파일·스킬을 가리키는지 (594건) |
| `test_agents_routing.py` | AGENTS.md §0 표가 실재하는 것만 가리키는지 |
| `test_doctor_sentinel.py` | 시크릿 검사 자신이 제대로 작동하는지 (진짜 키 차단 + 플레이스홀더 통과) |
| `test_body_typo_lint.py` | 오타 검사가 제대로 잡고 제대로 넘기는지 |
| `test_doi_verify.py` | DOI 검증이 가짜 DOI를 실제로 잡는지 |
| `test_assumption_check.py` | 통계 도구가 정답을 아는 데이터에서 맞는 검정을 지목하는지 |

**검사 도구 자신도 테스트한다**는 점이 중요합니다. 게이트가 조용히 고장 나면,
그 게이트가 지키던 산출물이 전부 무검증으로 나가기 때문입니다.

### 이 툴킷을 직접 고칠 때

스킬을 추가하거나 문서를 고쳤다면, **반드시** 아래를 다시 돌리세요.

```bash
python scripts/make_checksums.py --apply   # 파일 목록·해시 갱신
python doctor.py                           # PASS 확인
```

특히 **문서에 "`scripts/foo.py`를 실행하라"고 쓸 때는 그 파일이 실제로 있는지**
확인하세요. 없는 파일을 가리키는 문서가 이 패키지에서 가장 흔한 고장이었고,
그래서 `test_skill_references.py`로 자동 검사하게 만들었습니다.

## 6. AI가 길을 잃었을 때 하는 말

| 상황 | 이렇게 말하세요 |
|---|---|
| 엉뚱한 스킬을 쓰는 것 같다 | "AGENTS.md §0 라우팅 표에서 맞는 경로를 찾아서 그대로 해줘" |
| 검증 없이 "다 됐다"고 한다 | "§0의 게이트를 실행하고 결과를 보여줘" |
| 숫자를 어디서 가져왔는지 모르겠다 | "이 숫자가 어느 파일 어느 줄에서 나왔는지 보여줘" |
| 없는 파일을 실행하려 한다 | "그 파일이 실제로 있는지 먼저 확인해줘" |
| 워드 파일이 이상해졌다 | "docx_preflight.py랑 word_validate.py 돌려줘" |
