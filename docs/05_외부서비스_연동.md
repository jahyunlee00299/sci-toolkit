# 외부 서비스 연동 — 메일·GitHub·Asana/Notion·캘린더를 AI에게 안전하게 맡기기

이 문서는 "AI 에이전트가 우리 랩이 실제로 쓰는 외부 서비스(메일, GitHub, Asana/Notion, 캘린더·공유 시트)에
접속하게 하려면 어떻게 해야 하는가"를 초심자 눈높이에서 설명합니다.
핵심은 딱 하나입니다. **연결은 쉽게, 발송은 신중하게.**

---

## 0. 들어가기

AI 에이전트가 진짜 쓸모 있어지는 순간은 "내 메일함을 읽고 정리해준다", "내 GitHub 저장소 코드를 고쳐준다",
"내 할 일 목록(Asana/Notion)을 확인하고 캘린더 일정을 잡아준다" 같은 작업을 할 때입니다.
그러려면 AI가 이 서비스들에 접속할 수 있어야 하는데, "접속시키는 것"과 "안전하게 접속시키는 것"은 다른 이야기입니다.

이 문서를 읽고 나면 아래 세 가지를 알게 됩니다.

1. 왜 이 툴킷이 **MCP 연결을 지양**하고 **REST 커넥터 스크립트(`scripts/connectors/`)를
   기본값**으로 삼는지, MCP는 정말 대체 수단이 없을 때만 최후의 수단으로 쓰는 이유
2. 토큰(출입증)을 **안전하게 지키는 법**
3. 왜 AI가 메일이나 메시지를 **직접 발송하지 않고 초안에만 저장**해야 하는지

## 1. 연결은 REST 커넥터가 있으면 그걸 먼저

`docs/02_API와_MCP.md`에서 설명했듯, MCP는 "AI와 외부 서비스를 연결하는 표준 플러그 규격"이고
버튼 하나로 연결됩니다. 쉽다는 건 사실이지만, 그 대가로 **계정 전체에 상시로 열린 통로**가
생긴다는 것도 사실입니다 — 이번 작업과 무관해도 항상 열려 있고, 범위를 눈으로 확인하거나
작업 단위로 껐다 켰다 하기 어렵습니다. 그래서 이 툴킷은 **MCP 연결을 지양**하고, 순서를
이렇게 둡니다.

> 1순위 (기본값) — 이미 커넥터가 있는 서비스(메일·GitHub·Asana·Notion)는 **MCP로 연결하지
>   말고** `scripts/connectors/`의 REST 스크립트를 쓴다. 개인 토큰을 하나 발급받아 등록하면
>   끝이고, 발급은 브라우저로 로그인 → 계정 설정 → "토큰 만들기" 몇 번 클릭이면 됩니다
>   (`docs/02_API와_MCP.md` §5, `scripts/connectors/README.md`).
> 2순위 (임시 방편, 권장 아님) — 아직 커넥터가 없는 서비스(캘린더, 공유 시트)만 어쩔 수 없이
>   당분간 MCP 연결(버튼)을 씁니다. 데스크톱 앱(또는 Claude Code) 설정에서
>   "연결하기(Connect)" 버튼을 누른다 → 로그인 창이 뜬다 → 로그인한다 → 끝이지만, 커넥터가
>   생기는 즉시 1순위로 넘어가는 걸 목표로 삼으세요.
> 3순위 (유일한 정당한 예외) — 웹페이지를 직접 보고 클릭해야 하는 탐색성 작업은 애초에
>   REST로 대체할 수 없으니 MCP(Chrome 연결)를 그대로 씁니다.

커넥터로 전환을 마친 서비스는, 그 서비스의 MCP 연결을 앱 설정에서 **바로 해제**하세요 —
"필요할 수도 있으니 일단 켜둔다"가 아니라, 이번 작업에 필요한 범위만 열어두는 게 원칙입니다.
연결 해제는 계정 설정을 바꾸는 동작이라 AI가 대신 눌러주지 않고, 본인이 직접 하는 동작입니다.

> **정리**: MCP는 "일단 편하니까 쓰는 기본값"이 아니라 **REST 커넥터를 못 만들 때의 대체
> 수단**입니다. 이미 REST 커넥터가 있는 서비스라면 MCP로 연결하지 마세요 — 없는 서비스만
> 커넥터가 생기기 전까지 예외로 MCP 버튼을 씁니다.

## 2. 토큰·비밀번호 안전하게 지키기

앞서 배운 비유를 다시 씁니다.

> **토큰/API 키/비밀번호 = 출입증**

출입증을 함부로 다루면 안 되는 이유는 명확합니다 — 출입증을 주운 사람이 내 이름으로 건물을 드나들 수 있기 때문입니다.
아래 원칙만 지키면 됩니다.

- **채팅창에 토큰을 붙여넣지 않기.** AI에게 "이 토큰 써서 연결해줘"라며 토큰 문자열을 대화창에 그대로 타이핑하지 마세요.
  연결은 앱의 "연결하기" 버튼이나 전용 설정 화면에서 이루어져야 합니다.
- **코드나 커밋에 토큰을 넣지 않기.** 토큰을 스크립트 안에 직접 써넣고 그 파일을 GitHub에 올리면,
  전 세계 누구나 그 토큰을 볼 수 있게 됩니다. 실수로 공개 저장소에 올라간 토큰은 **몇 분 안에 자동으로 스캔당해 악용**되는 경우가 흔합니다.
- **토큰은 앱의 안전한 저장소에.** 앱이 제공하는 "연결(Connection)" 기능을 쓰면 토큰은 암호화된 곳에 보관됩니다.
  텍스트 파일에 토큰을 따로 적어서 바탕화면이나 공유 폴더에 두지 마세요.
- **유출되면 즉시 폐기(rotate/revoke).** 실수로 토큰이 노출됐다면, 해당 서비스 설정에서 그 토큰을 무효화하고 새로 발급하세요.
  "누가 악용하기 전에 먼저 문을 잠근다"는 원칙입니다.

### GitHub는 특히 조심할 것 — 원본 저장소(fork) 문제

랩 코드 중에는 다른 사람의 공개 저장소를 "복사(fork)"해서 우리 것으로 고쳐 쓰는 경우가 있습니다.
이때 저장소에는 "원본(upstream)"이라는 연결이 남아있을 수 있습니다.

- **미공개 연구가 실수로 공개될 위험**: 원본 저장소는 대개 전 세계에 공개되어 있습니다.
  내가 고친 내용(아직 발표 전인 연구 코드·데이터)을 실수로 원본 쪽에 올리면, 미공개 연구가 그대로 공개돼버릴 수 있습니다.
- **원칙**: 내 작업은 **내 복사본(fork)에만** 올립니다. 원본 저장소에 올리는 행동은 AI가 알아서 하지 않고,
  반드시 사람이 "그래, 이건 원본에 올려도 돼"라고 명시적으로 확인한 뒤에만 진행해야 합니다.
- 이걸 몰라도 괜찮습니다 — 안전하게 설정된 AI 에이전트라면 원본 저장소로 올라가는 작업을 만나면 자동으로 멈추고 물어봅니다.
  이 문서에서 여러분이 기억할 건 "원본에 올리는 건 항상 한 번 더 확인받는 일"이라는 사실뿐입니다.
- 공개 저장소 일반 원칙도 동일합니다: **미공개 연구·개인정보·자격 증명이 담긴 내용은 공개 저장소에 절대 올리지 않습니다.**

## 3. ⭐ 나가는 건 초안까지만 — 자동으로 보내지 않기

**이 문서에서 가장 중요한 원칙입니다.**

메일을 보내거나, Asana에 할 일을 등록하거나, 캘린더에 다른 사람을 초대하는 일 — 이런 건 전부 **"내 손을 떠나 남에게 전달되는 행동"**입니다.
한번 나가면 되돌리기 어렵습니다. 보낸 메일을 취소할 수 없고, 이미 배정된 할 일 알림은 이미 상대방 휴대폰에 떴을 수 있습니다.

그래서 원칙은 이렇습니다.

> **AI는 초안(Drafts)/임시보관함까지만 만들고, 발송 버튼은 누르지 않습니다.**
> **여러분이 내용을 확인하고, 보내고 싶으면 그때 본인이 직접 누릅니다.**

구체적으로는:

- **메일**: AI가 답장이나 새 메일을 작성해서 **임시보관함(초안)에 저장**합니다. 여러분이 열어서 확인 후 직접 "보내기"를 누릅니다.
- **Asana/Notion에 할 일 등록**: 다른 사람에게 실제로 배정되는 작업, 남에게 보이는 코멘트 작성은 먼저 내용을 보여주고 확인받습니다.
- **캘린더 초대**: 나 혼자 보는 일정이면 바로 등록해도 괜찮지만, **다른 사람을 초대하는 일정**(참석자 추가)은 확인 후 진행합니다.
- **공유 데이터 삭제**: 랩 공유 시트나 공유 폴더에서 데이터를 지우는 것도 "되돌리기 어려운 행동"이므로 먼저 확인받습니다.

### 왜 이렇게 하나요?

- 외부로 나가는 행동은 **되돌릴 수 없습니다.** 잘못 보낸 메일은 이미 상대방이 읽었을 수 있습니다.
- AI가 아무리 잘 썼어도, **최종 발송 버튼은 사람이 눌러야** 실수를 한 번 더 걸러낼 수 있습니다.
- "AI가 사람 대신 발송 버튼을 누르지 않는다"는 이 원칙 하나만 지켜도, 대부분의 사고를 예방할 수 있습니다.

## 4. 서비스별 안내

### 4-1. 메일 (학교/업무 메일 + 개인 메일)

랩에서는 보통 두 종류의 메일을 씁니다 — 학교/조직에서 제공하는 업무용 메일(예: 조직 전용 메일 시스템)과
개인 메일(예: Gmail)입니다. 둘 다 원칙은 같습니다.

- **연결**: `scripts/connectors/mail_connector.py`(IMAP/SMTP)를 씁니다. 메일 앱 비밀번호를
  발급받아 `python scripts/connectors/register_token.py mail --account work`(또는
  `personal`)로 등록하거나, 환경변수(`SCITK_MAIL_WORK_PASSWORD` 등)로 등록하면 끝입니다 —
  Chrome으로 발급 화면까지 안내받으려면 `docs/13_토큰_발급_Chrome으로_받기.md` §5, 자세한
  구조는 `scripts/connectors/README.md` §1. 커넥터를 쓰기로 했다면 그 메일 서비스의 MCP
  연결은 해제해도 됩니다.
- **읽기(검색·열람)**: 내 받은편지함을 읽고 정리하는 건 안전한 작업입니다 — AI가 바로 해도 됩니다.
- **쓰기(답장·새 메일)**: AI가 초안을 작성해서 **임시보관함에 저장**합니다(`draft`/`reply`
  서브커맨드는 SMTP를 아예 호출하지 않습니다). 여러분이 확인 후 직접 발송합니다.
- 학교/업무 메일과 개인 메일을 헷갈리지 않도록, "이 메일은 어느 계정으로 보내야 하나"가 애매하면 AI가 먼저 물어보게 하세요.

### 4-2. GitHub (코드 저장소)

- **연결**: `scripts/connectors/github_connector.py`를 씁니다. GitHub 계정 설정에서
  최소 권한으로 토큰(Personal Access Token)을 발급받아 `SCITK_GITHUB_TOKEN` 환경변수로
  등록합니다. 발급받은 토큰은 위 2장의 원칙(채팅창에 붙여넣지 않기, 코드에 넣지 않기)을
  그대로 지키세요. 커넥터로 넘어갔다면 GitHub MCP 연결은 해제해도 됩니다.
- **읽기(코드 조회·이슈 확인)**: 안전한 작업 — 바로 해도 됩니다.
- **쓰기(커밋·푸시·PR 생성)**: 내 복사본(fork)이나 내 브랜치에 올리는 건 대체로 괜찮지만,
  **원본 저장소(upstream)나 main/master 브랜치에 직접 올라가는 행동**은 반드시 확인 후 진행합니다.
- **공개 여부 확인**: 저장소가 공개(public)인지 비공개(private)인지 헷갈리면, 미공개 연구 자료를 절대 올리지 않도록 먼저 확인하세요.

### 4-3. Asana / Notion (과제·문서 관리)

- **연결**: `scripts/connectors/asana_connector.py` / `notion_connector.py`(및
  `notion_db_connector.py`)를 씁니다. 각 서비스 설정에서 개인 토큰을 발급받아
  `SCITK_ASANA_TOKEN` / `SCITK_NOTION_TOKEN`으로 등록합니다. 커넥터로 넘어갔다면
  Asana/Notion MCP 연결은 해제해도 됩니다.
- **읽기(내 할 일 확인, 문서 검색)**: 안전한 작업 — 바로 해도 됩니다.
- **쓰기(할 일 생성·수정, 문서 편집)**: 나만 보는 개인 메모나 초안 성격의 문서는 바로 만들어도 괜찮습니다.
  하지만 **다른 사람에게 할 일을 배정하거나, 다른 사람이 보는 문서에 댓글을 다는 것**처럼 남에게 영향을 주는 행동은
  먼저 내용을 보여주고 확인받으세요.
- 랩에서 정한 문서/할 일 등록 규칙(어느 게시판에 무엇을 올리는지)이 있다면 그 규칙을 AI에게도 알려주면 실수가 줄어듭니다.

### 4-4. 캘린더 / 공유 스프레드시트

- **연결**: 캘린더(예: Google Calendar), 공유 시트(예: Google Sheets, 랩 공유 스프레드시트)는
  **아직 REST 커넥터가 없는 예외 서비스**입니다. 커넥터가 없는 동안은 앱 연결 버튼(MCP)으로
  처리하고, 필요해지면 아래 "참고"의 안내대로 커넥터를 직접 만들어 넘어가세요.
- **읽기(일정 확인, 시트 데이터 조회)**: 안전한 작업 — 바로 해도 됩니다.
- **쓰기(일정 등록, 시트 값 수정)**:
  - 나 혼자만 보는 개인 일정 등록, 내 개인 메모 시트 수정은 바로 진행해도 괜찮습니다.
  - **다른 사람을 초대하는 일정**, **랩 전체가 같이 보는 공유 시트의 값 변경/삭제**는 먼저 무엇을 바꿀지 보여주고 확인받으세요.
    특히 공유 시트는 여러 사람이 같이 쓰는 자료라서, 실수로 값을 지우면 다른 사람의 작업에도 영향을 줍니다.
- **참고**: 캘린더·시트는 위처럼 **앱의 MCP 연결(버튼)로 지금 당장** 쓸 수 있습니다. 다만
  메일·GitHub·Asana·Notion 과 달리 **명령줄 스크립트 커넥터는 아직 없습니다**(구글 인증 방식
  때문) — 이 툴킷의 기본 원칙(REST 커넥터 우선)에서 벗어난 **유일한 예외**이지, 캘린더·시트도
  MCP가 더 낫다는 뜻은 아닙니다. 스크립트로 넘어가고 싶다면 `scripts/connectors/README.md`
  의 안내를 따라 직접 추가할 수 있습니다.

## 5. 어떤 건 물어보고, 어떤 건 그냥 하나

기준은 단순합니다. **"내 것만 읽는가, 남에게 영향을 주는가"**입니다.

| 그냥 해도 되는 것 (읽기·내부용) | 확인받아야 하는 것 (쓰기·외부/공유용) |
|---|---|
| 내 받은편지함 읽기·검색 | 메일 발송 (→ 초안까지만) |
| 내 GitHub 저장소/이슈 조회 | 원본 저장소·main 브랜치에 푸시 |
| 내 Asana/Notion 할 일 확인 | 남에게 할 일 배정, 공개 문서 댓글 |
| 내 캘린더 일정 확인 | 다른 사람을 초대하는 일정 등록 |
| 공유 시트 데이터 읽기·분석 | 공유 시트 값 수정·삭제 |
| 내 개인 메모/초안 작성 | 다른 사람이 보는 자료 수정 |

한마디로: **읽는 건 다 괜찮고, 남에게 나가거나 되돌리기 어려운 건 항상 확인받거나 초안까지만 만듭니다.**

## 6. Codex 팁

- Codex를 비롯한 다른 AI 코딩 도구도 GitHub, 메일, 캘린더 등을 연동할 때 같은 원칙이 적용됩니다:
  **REST 커넥터가 있으면 그걸 먼저, 없으면 MCP/토큰 연결로, 발송·삭제·배정 같은 되돌리기
  어려운 행동은 항상 사람 확인을 거칩니다.**
- 특히 GitHub 연동 시 "원본(upstream) 저장소에 푸시하지 않기" 원칙은 어떤 AI 도구를 쓰든 동일하게 지켜야 합니다.
  도구가 다르다고 원칙이 달라지지 않습니다.
- 여러 AI 도구를 함께 쓰는 경우, `docs/04_AI에게_규칙주기.md`에서 설명한 `AGENTS.md`/`CLAUDE.md`에
  "메일은 항상 초안까지만", "원본 저장소 푸시는 확인 후" 같은 규칙을 적어두면 도구가 바뀌어도 원칙이 유지됩니다.

## 7. 한 줄 요약

- **연결** = 메일·GitHub·Asana·Notion은 `scripts/connectors/`의 **REST 커넥터를 먼저** 쓰고,
  전환했으면 그 서비스의 MCP는 해제. 아직 커넥터가 없는 캘린더·시트만 MCP 버튼이 기본값
- **토큰/비밀번호** = 출입증 — 채팅창·코드·공개 저장소에 절대 노출 금지, 앱의 안전한 저장소에만
- **GitHub 원본(upstream) 저장소** = 내 복사본(fork)에만 올리고, 원본에 올라가는 건 항상 사람이 확인
- **⭐ 가장 중요한 원칙**: 메일·할 일 배정·일정 초대처럼 **외부로 나가는 것은 초안까지만** 만들고, 발송은 항상 여러분이 직접
- **판단 기준** = 읽기(내 것 확인)는 그냥 진행, 쓰기(남에게 영향)는 확인받거나 초안까지만
