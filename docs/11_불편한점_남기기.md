# 11. 불편한 점 남기기

툴킷을 쓰다 막히거나 이상한 걸 발견했을 때, 그 자리에서 기록으로 남기는 방법입니다.

## 왜 남기나요

막히면 대부분 어떻게든 우회하고 넘어갑니다. 그런데 그 우회법은 여러분 머릿속에만
남고, 다음 사람이 똑같은 곳에서 또 막힙니다. **기록된 불편만 고쳐집니다.**

"이 정도는 내가 잘못 쓴 거겠지"라고 생각되는 것도 남겨 주세요. 여러 명이 같은 데서
잘못 쓴다면 그건 사용자 잘못이 아니라 도구 잘못입니다.

## 가장 쉬운 방법 — 그냥 말하기

Claude Code에게 평소처럼 말하면 됩니다.

> "docx 표 편집이 자꾸 실패하는데 이거 좀 불편해요"
> "이런 기능이 있으면 좋겠는데 없네요"
> "이거 왜 안 되는지 모르겠어요"

이러면 Claude가 **한 번만** 되물어서 (보통 "그래서 원래는 어떻게 되길 기대하셨어요?")
빠진 부분을 채우고 기록해 줍니다. 캐묻지 않습니다 — 이미 짜증난 상태에서 취조당하면
아무도 신고를 안 하니까요.

기록되면 "기록했습니다 — <ID>" 같은 한 줄이 나옵니다.

## 직접 남기고 싶다면

```bash
python scripts/feedback_log.py add "표 안에서 find-replace 가 계속 실패합니다"
```

더 자세히 (전부 선택사항입니다 — 모르면 빼세요):

```bash
python scripts/feedback_log.py add "표 안에서 find-replace 가 계속 실패합니다" \
    --kind bug \
    --skill docx \
    --expected "표 셀 값이 바뀜" \
    --actual "51 matches 라는 메시지만 반복"
```

`--kind` 는 다섯 가지 중 하나입니다.

| 값 | 언제 |
|---|---|
| `bug` | 분명히 잘못 동작한다 |
| `friction` | 되긴 되는데 불편하다 (기본값) |
| `missing` | 있어야 할 기능이 없다 |
| `docs` | 문서가 틀렸거나 부족하다 |
| `idea` | 이러면 더 좋겠다 |

## 남긴 것 확인하기

```bash
python scripts/feedback_log.py list
```

`*` 표시는 아직 관리자에게 전달되지 않은 항목입니다.

## 어디에 저장되나요

`out/feedback.jsonl` — **여러분 컴퓨터의 파일 하나**입니다.

**기록하는 데는** GitHub 계정도, 토큰도, 인터넷 연결도 필요 없습니다. 일부러
그렇게 만들었습니다. USB로 툴킷을 받은 첫날에도 바로 남길 수 있어야 하니까요.

## 관리자에게 어떻게 전달되나요

`out/feedback.jsonl` 은 git 에 커밋되지 않습니다(`.gitignore` 로 막혀 있습니다).
그러니 그냥 두면 그 파일은 여러분 컴퓨터 밖으로 나가지 않습니다. 전달하려면
**여러분이 한 번 실행**해야 합니다.

```bash
python scripts/feedback_log.py export --github --repo <관리자가 알려준 저장소> --write
```

이때만 GitHub 계정이 필요합니다(이슈를 쓸 수 있는 권한이면 충분하고, 저장소
쓰기 권한은 필요 없습니다). 계정을 만들고 싶지 않다면 `--github` 없이 실행해
본문만 출력한 뒤, 그 내용을 관리자에게 직접 전달해도 됩니다.

## 남기면 안 되는 것 — 이건 코드가 막습니다

이 기록은 **다른 사람에게 전달됩니다.** 그래서 아래 것들이 들어 있으면
`export` 가 **실행을 거부합니다.** 안내문이 아니라 실제 검사입니다.

- 비밀번호·API 키·토큰
- 다른 사람의 개인정보 (이름, 이메일, 전화번호)
- 아직 발표하지 않은 연구 내용 (효소명, 균주, 수치, 미공개 서열 등)
- 사용자 이름이 드러나는 절대경로 (`C:\Users\...`, `/home/...`)

"무엇이 실패했는가"를 적으시고, "무슨 데이터로 실패했는가"는 빼세요.
예: `"D-갈락토스 12.4 g/L 데이터에서 실패"` 대신 `"HPLC csv 파일에서 실패"`.

수치는 단위가 붙은 것(`12.4 g/L`)뿐 아니라 **그냥 숫자도** 걸립니다.
`"수율이 92 였습니다"` 는 막히고, `"수율 파일 3개가 안 열립니다"` 는 통과합니다.
개수·순서·시간·쪽수처럼 **세는 숫자**는 값이 아니라고 보기 때문입니다.

기록할 때(`add`)는 막지 않고 경고만 합니다 — 그 자리에서 고치시라고요.
실제로 막히는 건 밖으로 나가는 `export` 단계입니다.

```
⚠ 밖으로 내보낼 수 없는 내용이 들어 있습니다:
  · [what] 연구 수치: 12.4 g/L
  · [actual] 절대경로: C:\Users\...
```

검사가 틀렸다고 판단되면 `--approve` 를 붙여 넘길 수 있습니다. 다만 그건
검사 결과를 통째로 무시하므로, 내용을 직접 확인한 뒤에만 쓰세요.

무엇이 걸리는지 미리 확인하고 싶다면 문장 하나만 따로 검사할 수 있습니다.

```bash
python scripts/feedback_sanitize.py "여기에 쓸 내용을 넣어보세요"
```

## 담당자는 누가 되나요 — 기본은 발견한 사람 본인

이슈를 관리자에게 몰아주지 않습니다. `--github --write`로 실제로 올릴 때, 아무 옵션도
안 주면 **그 명령을 실행한 계정(GitHub 토큰의 주인 = 대부분 발견한 사람 본인)** 에게
자동으로 할당됩니다. 다른 사람을 지정하거나 아예 할당하지 않을 수도 있습니다.

```bash
python scripts/feedback_log.py export --github --repo owner/name --write
# 기본값: 실행한 사람 본인에게 할당

python scripts/feedback_log.py export --github --repo owner/name --assignee other-login --write
# 다른 사람을 지정

python scripts/feedback_log.py export --github --repo owner/name --no-assignee --write
# 아무에게도 할당하지 않음
```

담당자 자동 조회(`/user`)가 실패해도(오프라인 등) 이슈 생성 자체는 막히지 않습니다 —
할당 없이 올라갑니다.

## 관리자용

```bash
python scripts/feedback_log.py list --pending          # 아직 안 올린 것
python scripts/feedback_log.py export                  # 이슈 본문 미리보기
python scripts/feedback_log.py export --github --repo owner/name --write
```

`--write` 없이는 미리보기만 합니다 (AGENTS.md §9 draft-first).
각 이슈에는 기록 ID·시각·OS·Python/Claude Code 버전이 자동으로 붙어서,
다시 물어보지 않고도 재현을 시작할 수 있습니다. 파일 경로·사용자 이름·
호스트명은 수집하지 않습니다.

정화 게이트는 미리보기에도 적용됩니다 — 미리보기만 통과시키면 그 출력을
복사해 손으로 올리는 우회가 생기고, 그 경로에는 아무 검사도 없기 때문입니다.

게이트가 무엇을 잡고 무엇을 통과시키는지는 `tests/test_feedback_sanitize.py`
가 계약으로 고정합니다. 거기 담긴 차단 케이스는 **실제로 일어났던 유출**이니,
오탐이 성가시다고 케이스를 지우지 말고 게이트 쪽을 고치세요.
