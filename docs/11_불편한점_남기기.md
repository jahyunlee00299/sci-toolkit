# 11. 불편한 점 남기기

툴킷을 쓰다 막히거나 이상한 걸 발견했을 때, 그 자리에서 기록으로 남기는 방법입니다.

## 왜 남기나요

막히면 대부분 어떻게든 우회하고 넘어갑니다. 그런데 그 우회법은 여러분 머릿속에만
남고, 다음 사람이 똑같은 곳에서 또 막힙니다. **기록된 불편만 고쳐집니다.**

"이 정도는 내가 잘못 쓴 거겠지"라고 생각되는 것도 남겨 주세요. 여러 명이 같은 데서
잘못 쓴다면 그건 사용자 잘못이 아니라 도구 잘못입니다.

## 가장 쉬운 방법 — 그냥 말하기

Claude Code에게 평소처럼 말하면 됩니다.

> "docx 표 편집이 자꾸 실패하는데 이거 좀 불편해요"
> "이런 기능이 있으면 좋겠는데 없네요"
> "이거 왜 안 되는지 모르겠어요"

이러면 Claude가 **한 번만** 되물어서 (보통 "그래서 원래는 어떻게 되길 기대하셨어요?")
빠진 부분을 채우고 기록해 줍니다. 캐묻지 않습니다 — 이미 짜증난 상태에서 취조당하면
아무도 신고를 안 하니까요.

기록되면 "기록했습니다 — <ID>" 같은 한 줄이 나옵니다.

## 직접 남기고 싶다면

```bash
python scripts/feedback_log.py add "표 안에서 find-replace 가 계속 실패합니다"
```

더 자세히 (전부 선택사항입니다 — 모르면 빼세요):

```bash
python scripts/feedback_log.py add "표 안에서 find-replace 가 계속 실패합니다" \
    --kind bug \
    --skill docx \
    --expected "표 셀 값이 바뀜" \
    --actual "51 matches 라는 메시지만 반복"
```

`--kind` 는 다섯 가지 중 하나입니다.

| 값 | 언제 |
|---|---|
| `bug` | 분명히 잘못 동작한다 |
| `friction` | 되긴 되는데 불편하다 (기본값) |
| `missing` | 있어야 할 기능이 없다 |
| `docs` | 문서가 틀렸거나 부족하다 |
| `idea` | 이러면 더 좋겠다 |

## 남긴 것 확인하기

```bash
python scripts/feedback_log.py list
```

`*` 표시는 아직 관리자에게 전달되지 않은 항목입니다.

## 어디에 저장되나요

`out/feedback.jsonl` — **여러분 컴퓨터의 파일 하나**입니다.

GitHub 계정도, 토큰도, 인터넷 연결도 필요 없습니다. 일부러 그렇게 만들었습니다.
USB로 툴킷을 받은 첫날에도 바로 기록할 수 있어야 하니까요.

관리자가 나중에 모아서 이슈로 올립니다. 여러분이 할 일은 없습니다.

## 남기면 안 되는 것

이 파일은 **다른 사람에게 전달됩니다.** 그러니 넣지 마세요:

- 비밀번호·API 키·토큰
- 다른 사람의 개인정보
- 아직 발표하지 않은 연구 내용 (효소명, 균주, 수치, 미공개 서열 등)

"무엇이 실패했는가"를 적으시고, "무슨 데이터로 실패했는가"는 빼세요.
예: `"D-갈락토스 12.4 g/L 데이터에서 실패"` 대신 `"HPLC csv 파일에서 실패"`.

## 관리자용

```bash
python scripts/feedback_log.py list --pending          # 아직 안 올린 것
python scripts/feedback_log.py export                  # 이슈 본문 미리보기
python scripts/feedback_log.py export --github --repo owner/name --write
```

`--write` 없이는 미리보기만 합니다 (AGENTS.md §9 draft-first).
각 이슈에는 기록 ID·시각·OS·Python/Claude Code 버전이 자동으로 붙어서,
다시 물어보지 않고도 재현을 시작할 수 있습니다.
