# Reference Surveyor (Code Case Investigation) — P1.5 Dedicated

Skill for public repo exploration, code analysis, mapping document creation.

## Pipeline Location

```
P1 (Academic Review) → [P1.5 Reference Survey] → P2 (Implementation)
```

## Execution Method

- Repo exploration: WebSearch parallel calls (Papers With Code + GitHub simultaneous)
- Repo evaluation: Bash with `gh repo view` etc. direct confirmation
- Example execution: Bash clone → venv → pip install → run

## Prerequisites

- P1 requirement document completed
- Search keywords prepared

---

## Step 1.5-1: Repo Exploration (Team Parallel)

### Search Source Priority

1. Direct paper links (Code Availability, supplementary)
2. Papers With Code
3. GitHub direct search
4. Package documentation examples
5. Community (Stack Overflow, Reddit)

Search rule: minimum 2 times, 1-6 words, no query repetition

---

## Step 1.5-2: Repo Evaluation & Selection

Evaluate each on 5-point scale: Executability, Code quality, Case similarity
License: MIT/Apache/BSD → PASS, none → FAIL
Python: 3.10+ → PASS

Select top 2-3 repos.

---

## Step 1.5-3: Code Analysis

```
[Structure]     Project directory structure?
[Entry point]   Main execution flow?
[Core logic]    Which file, which function has the algorithm I need?
[Data flow]     Input → transform → output data types and formats?
[Configuration] How are parameters managed?
[Dependencies]  Which libraries are used?
```

---

## Step 1.5-4: Example Execution Verification

Fork → Clone → venv → pip install → Run reference example → Save results

```
results/reference/
├─ reference_output.json
├─ reference_run_log.txt
└─ reference_params.yaml
```

---

## Step 1.5-5: Write Mapping Document

File: `docs/reference_mapping.md`

Core content:
- Original repo info (URL, Fork, commit hash, license)
- Mapping table (reference location ↔ my case location ↔ modification content)
- Classify: modification unnecessary / modification required items
- Dependency differences
- Reference execution results

---

## Pre-Work Confirmation (Ask if Unclear)

Before starting, if any of the following is unclear, **ask user rather than guessing**:
- Methodology/algorithm investigation scope
- Language/framework preference (Python only? R OK too?)
- License constraints (GPL allowed?)
- Fork need (read-only vs. actual modification planned)

## Completion Checklist (Report Against When Done)

```
✅ N reference repos explored, M selected
✅ Each repo evaluation scores (executability/quality/similarity)
✅ Example execution verification: passed/failed
✅ Mapping document docs/reference_mapping.md written
✅ Fork + upstream remote configured
✅ License confirmed
⬜ [List any missing items if present]
```

## Exit Condition

Deliverables: Forked repo + mapping document + reference execution results → P2

## Skill Integration

- Input: P1 requirement document, S3 search results
- Output: → P2 (code-implementer), → P3 (code-validator), → P4 (3-way comparison)
