# lab-record — Record Schema (v0.2, 261001)

Decisions fixed 261001: Markdown files (not a Notion DB) · no migration of old records ·
notifications off.

One lineage, four record types. Every record is a Markdown file with YAML frontmatter, stored
under one configurable root. Plain files on purpose: git-diffable, readable without any tool,
no server (eLabFTW-class ELNs are AGPL and need hosting — see prior-art note at the end).

```
PROT (method) ──used by──▶ EXP (run) ──interpreted in──▶ DISC (discussion) ──concludes──▶ DEC (decision)
     ▲                                                                                        │
     └──────────────── DEC.next: new PROT version / new EXP / manuscript section ◀────────────┘
```

The gap no surveyed tool fills is exactly this chain: being able to ask "which decision rests on
which run, under which protocol version?" and get an answer by following IDs, not memory.

## 1. Identifiers

| Type | Format | Example | Notes |
|------|--------|---------|-------|
| Protocol | `PROT-{NNN}` + `version: vN` | `PROT-007` v3 | Matches experiment-hub Mode 1 (`PROT-{N}`), zero-padded to 3 |
| Experiment run | `EXP-{YYMMDD}-{NN}` | `EXP-261001-02` | Date = run date, NN = order that day |
| Discussion | `DISC-{YYMMDD}-{NN}` | `DISC-261003-01` | |
| Decision | `DEC-{YYMMDD}-{NN}` | `DEC-261003-01` | |

- References always pin a version: `PROT-007@v3`. An unpinned `PROT-007` is a lint error.
- Legacy IDs (e.g. an older numbered workbook series) go into `aliases: [...]`; they are
  searchable but never used as the primary key.
- IDs are allocated by `lab_record.py new <type>` (scans existing files) — never hand-typed,
  so two sessions cannot collide silently (it re-scans right before writing).

## 2. Common frontmatter (all types)

```yaml
id: EXP-261001-02
type: exp                 # prot | exp | disc | dec
title: "Cascade run, 50 uL, additive A sweep"
status: draft             # draft | active | closed | superseded
owner: <person-key>       # key into the people map (shared + local config), never a real name in records
project: <YOUR_PROJECT>   # free tag; maps to a Notion project only via local config
created: 2026-10-01
updated: 2026-10-01
aliases: []
supersedes: null          # id of the record this one replaces (corrections = new record, see §4)
links: []                 # extra typed links, see below
```

`links[]` items (checked by lint; nothing is fetched, no network):

| Item | Checked as |
|------|------------|
| `{rel: see-also, id: "DISC-..."}` (any rel + `id`) | id must resolve (RULE2) |
| `{rel: asana, task: "<digits>"}` / `{rel: asana, project: "<digits>"}` | digits-only format (RULE2). Asana is read-only context; the gid is a citation, never a write target |
| `{rel: background, path: "..."}` | path exists (RULE7); topic folders of background material (M2 literature, vendor docs) |
| `{rel: legacy, path: "..."}` | path exists (RULE7); an old notebook file that is not migrated |
| `{rel: enzyme\|standard\|sheet, name: "<name or alias>"}` | name resolves in `<root>/catalog.json` and its path exists (RULE2, see Catalog) |
| unknown rel with neither `id`, `path`, `task`/`project` nor catalog `name` | RULE2 violation |

Path values (`raw_data`, `workbook`, `matrix_config`, `links[].path`) resolve against the root;
a value starting with `@/` resolves against the record's own `project` folder (see §5).

## 3. Type-specific fields

### PROT — method

```yaml
version: v3
changed_from: v2
change_reason: "additive A moved out of the premix (per-tube variable)"
references:               # condition rationale (experiment-hub Mode 1 auto-search)
  - {kind: paper, doi: "10.xxxx/...", applies_to: "pH, T"}
  - {kind: datasheet, source: "vendor sheet", applies_to: "enzyme units"}
conditions_default:       # the protocol's nominal conditions
  T_C: 37
  pH: 7.5
  buffer: "HEPES 50 mM"
  total_volume_uL: 50
matrix_config: matrix/PROT-007_v3.json   # optional: reaction_matrix.py config (Mode 10)
```
Body: materials · step-by-step method · analysis · safety/disposal · change history.
A new version = a new file `PROT-007_v3.md`; old versions stay (status `superseded`).

### EXP — run

```yaml
protocol: PROT-007@v3
conditions:               # ONLY what differs from protocol.conditions_default, plus the varied axis
  additiveA_mM: [0, 5, 10, 20]
deviations:               # unplanned changes during the run — the "unintended difference" class
  - "tube 3: enzyme added 2 min late"
raw_data: [data/EXP-261001-02/hplc_export.csv, "@/sub/run.csv"]   # root-relative, or @/ = project folder; never copied into the record
workbook: matrix/EXP-261001-02.xlsx              # generated by reaction_matrix.py, if any
outcome_summary: "conversion plateaus above 10 mM additive A"
```
Body: observations, outliers flagged (experiment-hub Mode 4), quick numbers. No interpretation here.

### DISC — discussion

```yaml
mode: M1                  # M1 interpret | M2 compare-literature | M3 discussion-structure | meeting
about: [EXP-261001-02, EXP-260928-01]   # required, >=1 EXP (or PROT for method debates)
participants: [<person-key>, ...]
context_checklist:        # research-discussion M1 mandatory context; missing = "unknown", never assumed
  T: ok
  pH: ok
  enzyme_conc: unknown
interpretations:
  - {rank: 1, stars: 3, claim: "...", evidence: [EXP-..., "doi:..."], test: "how to confirm"}
  - {rank: 2, stars: 2, claim: "...", evidence: [...], test: "..."}
excluded: [{claim: "...", reason: "..."}]
literature: ["doi:10.xxxx/..."]          # APA in body, DOI here
open_questions: ["..."]
```
Body: free discussion text; for M3 the 7-step Discussion skeleton; Interaction Matrix when
>=3 species in the reaction (research-discussion rule).

### DEC — decision (research ADR)

```yaml
from: [DISC-261003-01]    # required, >=1 DISC
decision: "Fix additive A at 10 mM for all downstream cascade runs"
alternatives: [{option: "20 mM", why_not: "no gain, higher phosphate background"}]
confidence: medium        # low | medium | high
revisit_if: "kinetic fit shows an additive-A inhibition term"
next:                     # what this decision spawns — closes the loop
  - {kind: protocol, id: PROT-007@v4}         # `id` only once the record exists (lint RULE2)
  - {kind: protocol, plan: "v4: additive A fixed at 10 mM"}   # not created yet -> `plan`, never a future id
  - {kind: experiment, plan: "repeat at 30 C"}
  - {kind: manuscript, target: "Results 3.2"}
  - {kind: task, external: "Notion/Asana card (proposal only, never auto-posted)"}
```

## 4. Integrity rules (enforced by `lab_record.py lint`)

1. **Closed records are append-only.** The single allowed frontmatter change is `status: closed → superseded` (set by `new prot --from-prot`). Once `status: closed`, the frontmatter is frozen; the body
   may only gain an `## Addendum (YYYY-MM-DD)` section. A correction is a NEW record with
   `supersedes:` (borrowed from elabmcp's append-only + provenance design). Lint compares against
   the last git commit when the root IS a git work-tree top level (not merely nested in one) and HEAD holds the record; otherwise against the hash stored by `close` (which is always written).
2. Every reference resolves: `protocol`, `about`, `from`, `next.id`, `supersedes`, `links`.
   Typed links are format-checked (asana `task`/`project` digits only; catalog `name` must exist
   in its kind and its path must exist; an entry with no id/path/task/project/name is a violation).
3. Every PROT reference is version-pinned.
4. No orphan DISC (empty `about`) and no orphan DEC (empty `from`).
5. `context_checklist` items are `ok | unknown | n/a` — no other values (prevents a silently
   assumed condition from looking checked).
6. No real names, emails or student IDs in shared files: `owner`/`participants` must be keys
   of the MERGED people map (shared `<root>/lab-record.config.json` + local config, local wins).
   The shared file should hold short keys/initials only; real names belong in each member's
   local config.
7. Path values exist: `raw_data`, `workbook`, `matrix_config`, `links[].path` (existence check
   only — never read, never mtime; cloud-sync-safe). A path starting with `@/` resolves against
   the record's `project` folder; a record without `project`, or a project without `folder`, is a
   RULE7 violation whose message names the missing piece.
8. No duplicate ids and no sync-conflict copies. (a) Two files with the same frontmatter id
   (PROT: same id AND same version) -> `RULE8 <id> duplicate id in <file1>, <file2>`; the
   canonically named file is listed first. (b) Every `*.md` under protocols/ experiments/
   discussions/ decisions/ must be named exactly `PROT-NNN_vN.md` (PROT) or `<id>.md` (others),
   else `RULE8 <file> filename does not match its id (sync-conflict copy?)` — what OneDrive /
   Dropbox leave behind (`EXP-261002-01-DESKTOP-AB12.md`, `EXP-261002-01 (1).md`). Such files are
   still parsed so the duplicate is reported, not skipped. `new` also refuses (exit 2) to
   allocate an id that any file name already claims, conflict copies included.
9. Catalog paths exist: every `catalog.json` entry whose path is missing ->
   `RULE9 catalog <kind>:<name> path missing: <path>`, reported once even if no record uses it.

## 5. Layout and configuration

```
<root>/
  protocols/PROT-007_v3.md
  experiments/2026/EXP-261001-02.md
  discussions/2026/DISC-261003-01.md
  decisions/2026/DEC-261003-01.md
  matrix/            # reaction_matrix.py configs + generated workbooks
  data/              # optional; raw_data may also point outside root
  INDEX.md           # GENERATED by `lab_record.py index` — never hand-edited
  lab-record.config.json   # optional SHARED config (people + projects), see below
  catalog.json             # optional catalog of named materials, see §5b
```

**Two config layers.**

1. *Local* config (`--config` or `~/.config/lab-record/config.json`, not committed, template =
   `config.example.json`):
```json
{
  "root": "<absolute path to the record root>",
  "people": {"person1": "local display name"},
  "projects": {"<YOUR_PROJECT>": {"folder": "../<PROJECT_FOLDER>"}}
}
```
2. *Shared* config `<root>/lab-record.config.json`, shipped inside the root so every member gets
   it with the folder. It provides `projects` and `people` only; a `root` key in it is ignored
   with a warning on stderr. Malformed shared file -> exit 2.

Root precedence: `--root` > env `LAB_RECORD_ROOT` > local `root` > **cwd walk-up** (nearest
ancestor directory containing `lab-record.config.json`). Merge: shared supplies `projects` and
`people`; local overrides per key (people) and per field (a project's fields); local-only keys are
added. So a member's local file can be just `{"people": {"person1": "My Name"}}`.

`projects.<key>` fields: `folder` (path relative to the root, e.g. `"../4. API Synthesis"`),
`asana_project` (digits-only gid string or `null`; any other value -> exit 2 at load; the example
file uses `null` so the template loads). Path values must use `/` separators (a backslash is a
RULE7/RULE9 violation; a `folder` containing one -> exit 2). A local `folder: null` does not erase
the shared value. **`@/` paths:** in any path value a
leading `@/` means "inside this record's project folder" (`@/sub/file.csv`); other relative paths
resolve against the root, and may point outside it (e.g. `../Primers.xlsx`). A `@/` path may not
leave the project folder: `@/../x`, `@//x`, `@/C:/x` -> `escapes project folder` (RULE7 for
records, RULE9 for catalog entries). Asana is read-only context here — see SKILL.md.

Notifications are off everywhere (design decision 261001). Writing a record never
posts anywhere; Notion/Asana follow-ups appear only as `DEC.next kind: task` proposals. A `notify`
or `projects.*.notion_project` key in a config is ignored (stderr note).

### 5b. Catalog (`<root>/catalog.json`, optional — absent = empty)

Named lab materials that records point at by name instead of free text:
```json
{"enzyme":   {"<name>": {"project": "<project key>", "path": "@/<path>", "aliases": ["..."], "note": "..."}},
 "standard": {"<name>": {"path": "<root-relative path>"}},
 "sheet":    {"<name>": {"path": "../Primers.xlsx"}}}
```
Kinds are exactly `enzyme | standard | sheet`; `path` is required and resolves like any path
(`@/` = the entry's own `project` folder). Unknown kind, unknown `project` key, an ambiguous
name/alias within a kind, or malformed JSON -> exit 2 at load. Records link entries with
`links: [{rel: enzyme, name: "<name or alias>"}]` (case-insensitive). Commands:
`uses <name>` (records linking the entry, plus PROT -> its EXPs and EXP -> its DISCs) and
`catalog [--kind K]` (table: kind, name, project, resolved path, exists, used_by).

Notebook files written before adopting lab-record are NOT migrated
(design decision 261001). New records start in this format; an old file is cited from a new record
via `links: [{rel: "legacy", path: "<relative path>"}]` — lint checks only that the path exists.
The root is any folder the user picks; the skill text never hardcodes one.

## 6. Queries the index must answer (acceptance condition)

- `trace DEC-x` → upstream chain DEC ← DISC ← EXP ← PROT@vN, with raw_data paths.
- `impact PROT-007@v3` → every EXP run on it and every DEC that rests on those runs
  (what to revisit when a protocol bug is found after the runs were done).
- `uses <catalog name>` → every record linking that enzyme/standard/sheet, and the runs and
  discussions downstream of it.
- `open` → DISC with open_questions, DEC with `revisit_if`, EXP never discussed.

## Prior art (261001 survey of public repositories; star counts verified the same day)

No surveyed tool links method records to discussion/decision records. Borrowed: append-only
edits + provenance block + permission profiles (tum-research-data-hub/elabmcp, MIT); skill
frontmatter + `license` field convention (K-Dense-AI/scientific-agent-skills, MIT). Not borrowed:
eLabFTW code (AGPL-3.0, incompatible with an MIT bundle) — data-model ideas only. External ELN
sync (protocols.io / Benchling / LabArchives) deferred to thin adapters over existing K-Dense skills.
