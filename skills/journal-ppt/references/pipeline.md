# journal-ppt Agent Pipeline

Per-agent prompts, distilled from `~/.claude/commands/journal-ppt-team.md` and updated to
reference `../references/style_spec.md` and `../scripts/deck_builder.py` /
`../scripts/qc_deck.py` instead of ad hoc styling decisions. Use this when orchestrating a
multi-agent build; for a single-session build, work through the phases yourself.

**Model routing (mandatory):** every `Agent()` spawn below names its model tier explicitly.
`agent_model_check.sh` blocks Haiku on anything touching academic nomenclature — the
Academic QC agent MUST be Sonnet. This was measured twice in the 2026-08-23 session as a
silent block, not a graceful fallback, so omitting `model=` is not a safe default here.

## Phase 0: Setup

Working dir: `~/.claude/cache/journal_ppt_<timestamp>/` (journal mode) or
`~/.claude/cache/research_ppt_<timestamp>/` (research mode). All agents save outputs here.

## Phase 1: Paper Download (journal mode) / Data Prep (research mode)

**journal mode** — resolve DOI/title via CrossRef/OpenAlex, download PDF (PDF-first policy:
curl + PyMuPDF, never WebFetch for paper content — WebFetch converts HTML and loses
figures). Extract figures (`fitz.extract_image`, fallback to 300 DPI page render + crop),
full text, and SI. This logic is unchanged from `journal-ppt-team.md` Agent 1 — reuse it
directly; it was not part of the measured 2026-08-23 failures. **Before extracting from the
PDF, apply the asset-sourcing rule from SKILL.md** — check for author-original exports
first.

**research mode** — check (in order): manuscript file (docx/PDF), data files (HPLC,
kinetic fits, BO results), figures already generated by `publication-figures`, verbal
description. Ask the user if key data files are not found.

## Phase 2: Content Analysis [Sonnet]

### Step 1: Parse paper/data structure
Abstract, Introduction (3-5 bullets), Methods (brief), Results (each finding mapped to a
figure/table + significance tier PRIMARY/SECONDARY/SKIP), Discussion, Conclusion.

### Step 2: Identify key figures
PRIMARY = main results, dose-response, kinetic data, key comparisons, graphical abstract.
SECONDARY = method schematics, supporting data. SKIP = small insets, purely statistical
supplemental figures. Write a 2-3 sentence explanation per figure; map label -> file path.

### Step 3: Novel contributions (3-5 bullets), Step 4: Discussion questions (4-6,
open-ended, suitable for journal club: methodological choices, limitations, alternative
interpretations, connections to the user's own research).

### Step 5: Content validation (MANDATORY, before anything reaches a slide)

**5a. Quantitative cross-verification** — compare each numeric claim against the
figure/table it references; flag discrepancies (e.g. text says R=0.73, caption says
r=0.72). Check sig-fig consistency. Verify percentages sum where applicable. Output
`validated_numbers: [{claim, source, match: true/false}]`.

**5b. Nomenclature normalization** (apply `academic-term-rules`, boundary-aware — a blind
`str.replace` on unit substrings corrupts ordinary words, e.g. "result"->"resμLt"; anchor
replacements on a preceding digit). Store normalized text + format flags:
```json
{"text": "kcat/Km = 3.4 s⁻¹·mM⁻¹", "format_flags": ["kcat:italic_subscript", "Km:italic_subscript"]}
```

**5c. Statistical claim validation** — "significant" needs an associated p-value/test;
verify R vs R² not confused; "n-fold increase" needs a numeric basis. Flag unsubstantiated
claims as `validation_warnings`.

**5d. Reference accuracy** — verify each key reference's DOI via OpenAlex/CrossRef; ISO 4
journal abbreviations; flag author/year mismatches. Output `references_validated: true/false`.

**5e. Table data validation** — units present in headers, numeric format consistent within
columns, nomenclature applied to cell values, empty/placeholder cells flagged.

### Step 6: References for the References slide (5-10 key citations).

### Step 7: Output `content_analysis.json`
```json
{
  "title": "...", "authors": "...", "journal": "...", "year": "...", "doi": "...",
  "abstract_summary": "...", "introduction_bullets": ["..."], "methods_summary": "...",
  "results": [{"finding": "...", "figure_label": "Figure 2", "figure_path": "assets/fig_p3_x12.png",
               "significance": "PRIMARY", "explanation": "...",
               "validated_numbers": [{"claim": "...", "source": "...", "match": true}]}],
  "novel_contributions": ["..."], "discussion_points": ["..."],
  "strengths": ["..."], "limitations": ["..."], "references": ["..."],
  "validation_warnings": ["..."],
  "speaker_notes": {"title": "...", "background_1": "...", "background_2": "..."}
}
```
This file is the number-verification checkpoint. A slide-writing step reads numbers FROM
this JSON, not by re-deriving them from raw paper text a second time.

## Phase 3: PPT Construction [Sonnet]

Read `SKILL.md` and `references/style_spec.md` FIRST. Use `scripts/deck_builder.py`'s
`Deck` class for every slide — do not hand-write python-pptx calls that bypass it, since
that is exactly how the type scale and line-spacing rules got violated in the 2026-08-23
session.

**Figure-First Layout (mandatory for any results slide with a figure):**
| Slide type | Figure area | Text area |
|---|---|---|
| Single figure | 55-65% | 35-45% sidebar/top strip |
| Full-width/multi-panel | 60-70% (bottom) | 30% top strip |
| Two figures side-by-side | 50% each | Minimal caption only |

Decision tree: figure gets 55-65% of the slide FIRST, text fits into what remains. If text
doesn't fit: reduce to <=3 bullets (1 line each) -> move detail to speaker notes -> if still
tight, caption-only (zero bullets). Font-size shrinking is never the fix — the type scale is
closed (`style_spec.md` §7).

Landscape figures -> bottom 55-65%, text above. Portrait/square -> right 55-60%, text left
sidebar. Multi-panel -> full-width bottom 60%, text strip above. `deck_builder.Deck.add_figure()`
implements the sizing/upscale/aspect-preserving logic; `Deck.figure_slide()` wraps the whole
pattern.

**Slide order (journal mode):** Title -> Authors & Affiliations -> Background/Motivation (2) ->
Methods -> Results (one slide per PRIMARY figure) -> Discussion -> Strengths/Limitations ->
Questions for Discussion -> References -> Thank You. 14-24 slides total, typical 16-19.

**Authors & Affiliations slide** (`Deck.authors_slide()`, added 260912): pull authors and
their numbered affiliation footnotes from page 1 of the paper (the same PDF-first pass as
Phase 1 already reads); group members under each institution rather than repeating a long
numbered-superscript block verbatim. Fetch each institution's official logo via
`logo_fetch.fetch_institution_logo()` -- Wikimedia Commons "original file" link first
(stable URL, public-domain/below-threshold-of-originality for most crests and wordmarks),
the institution's own official site as fallback only when no Commons entry exists. **Do not
skip this slide silently when a logo can't be found** -- render the affiliation bullets
without that one logo rather than dropping the whole slide; a partial attribution slide is
still correct, an omitted one is not. Downloading a file needs the user's go-ahead per
CLAUDE.md's file-download rule -- ask once per deck build, not once per logo.

**Slide order (research mode):** Title -> Background (2) -> Research Strategy -> Results (one
per experiment) -> Discussion & Significance -> Conclusions & Future Work -> Acknowledgments
& References.

**Table slides**: `Deck.table_slide()` handles header styling (navy bg, white bold text) and
zebra striping automatically. Apply nomenclature normalization to cell values before passing
them in (boundary-aware unit regex — see Phase 2 Step 5b).

**Language**: every slide-body string is English. Speaker notes are Korean, >=100 chars,
format `【Section — description】` header + talking points, at least 2-3 results slides
include "예상 질문:" + answer guide.

**Output filename**: `journal_club_YYYY-MM-DD_<Topic>.pptx` or
`research_seminar_YYYY-MM-DD_<Topic>.pptx`, saved to `~/presentations/` by default (or the
user-specified path).

## Phase 4: Academic QC [Sonnet — NOT Haiku, see model-routing note above]

1. Run `python scripts/qc_deck.py <pptx_path>` — this is the machine-checkable half (type
   scale, line spacing, geometry, language, notes, pictures, palette). Any CRITICAL finding
   blocks delivery.
2. Nomenclature spot-check beyond what `qc_deck.py` covers: species italics, gene/protein
   roman-vs-italic, EC number format, sub/superscripts not caught by a flat Hangul/font-size
   regex — reference `academic-term-rules` §12 `TYPO_PATTERNS`.
3. Cross-check quantitative claims on slides against `content_analysis.json`'s
   `validated_numbers` — flag any number that drifted during slide-writing.
4. Structure: IMRAD flow order, References slide present and last (or second-to-last before
   Thank You), IMRAD/discussion-questions ordering.
5. Save `qc_report.md` to the working directory (not just printed to the console).

**Quality gate loop**: if `qc_deck.py` exits non-zero, send the report back to Phase 3 for
revision. Maximum 2 revision cycles before delivering with the remaining warnings noted
explicitly (never silently deliver a CRITICAL-failing deck).

## Phase 4.5: Visual QC & Auto-Fixer [Sonnet]

1. Export slides to PNG (PowerPoint COM, `win32com.client`) or fall back to shape-geometry
   analysis if COM is unavailable.
2. Inspect for: font sizes below the closed-list floor, figures below 3in minimum, shapes
   crossing the Y=7.0in floor or side margins, overlapping shapes, large empty areas
   (>40% unused) or crammed content.
3. **Fix automatically** using `deck_builder` helpers where possible (re-run `add_figure()`
   with corrected bounds, re-run `bullets()` with a role that matches the closed list)
   rather than hand-patching raw XML.
4. Re-run `qc_deck.py` after fixing to confirm the fix actually worked — do not report a fix
   as done without an independent re-check pass (C-40 spirit: self-review of your own edit
   is not verification).

## Phase 5: Deliver

```
[DONE] PPT: <path>
       QC:  <qc_report.md path> -- VERDICT: <PASS|PASS WITH WARNINGS|FAIL>
       Slides: <N> | Figures inserted: <N>
```
